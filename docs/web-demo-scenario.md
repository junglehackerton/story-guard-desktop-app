# Story Guard 데모 시나리오

작성일: 2026-09-16

현재 웹 데모의 실제 화면·버튼·공개 샘플에 맞춘 체험 및 발표 시나리오다. 첫 방문에는 튜토리얼 커버가 먼저 나타나며, ‘열쇠 사례 시작하기’를 누르면 아래 체험으로 이어진다. 기본 체험은 저장된 실제 분석 결과로 진행한다. 아래 시간은 진행 목표이며 사용자 테스트로 측정한 시간이 아니다.

## 한 문장으로 전달할 가치

> 긴 소설에서 앞뒤가 달라진 설정과 검토할 단서를 원문 근거로 찾아주고, 최종 판단은 작가가 합니다.

## 방문자에게 주는 역할

당신은 소설 《백로호텔의 마지막 손님》의 다음 회차를 내보내기 전, 원고를 점검하는 작가입니다. 주인공 윤해주는 철거 직전 호텔의 비밀을 추적합니다. 작품 전체를 읽지 않아도 됩니다. 스토리 가드가 찾아낸 열쇠의 행적을 비교하고 검토 판단 하나를 남겨 보세요.

## 시나리오 1 — 잘라 버린 열쇠가 돌아왔다

**목적:** 회차 간 일관성 검토 → 근거 확인 → 작가 판단을 한 번에 경험한다.

**시작 상태:** 첫 방문은 튜토리얼 커버에서 시작한다. ‘당신의 상황’과 3단계를 읽은 뒤 ‘열쇠 사례 시작하기’를 누른다. 이미 튜토리얼을 본 브라우저에서는 첫 사례 화면이 바로 열리며, 화면의 ‘체험 안내 다시 보기’로 커버를 다시 열 수 있다. 반복 시연할 때는 자신의 체험 브라우저에서 ‘체험 판단 초기화’를 누른다. 저장된 샘플 원고는 바뀌지 않는다.

| 목표 시간 | 방문자 행동 | 화면에서 확인할 것 | 전달되는 가치 |
| --- | --- | --- | --- |
| 0:00–0:20 | ‘잘라 버린 열쇠가 다시 사용된다면?’을 읽는다. | 저장된 실제 분석 결과라는 표시와 짧은 작품 소개 | 원고 전체를 읽지 않아도 검토를 시작할 수 있다. |
| 0:20–0:55 | 3화·5화 인용문을 비교한다. ‘실제로 사용한 장면도 확인하기’를 펼친다. | 3화의 절단·폐기, 5화의 같은 열쇠·온전한 상태·자물쇠 사용 | 서로 떨어진 회차의 근거를 함께 확인한다. |
| 0:55–1:20 | ‘3화 전체 원문에서 확인’을 누른 뒤 ‘← 열쇠 사례의 근거 비교로 돌아가기’를 누른다. | 실제 원고의 해당 회차와 강조된 문장 | AI 설명을 원문 맥락으로 검증할 수 있다. |
| 1:20–1:45 | ‘문제 있음’, ‘문제 아님’, ‘판단 보류’ 중 하나를 선택한다. | 선택 표시와 ‘내 판단’ 안내 | AI가 오류를 확정하지 않고 작가가 결정한다. |
| 1:45–2:15 | ‘이 후보의 관계 지도 보기’를 누른다. | 열쇠를 중심으로 검토 근거와 관련된 관계, 필요한 경우 펼칠 수 있는 설명·원문 | 물건의 상태를 인물과 사건의 맥락에서 살펴본다. |
| 2:15–3:00 | ‘첫 사례로 돌아가기’ → ‘떡밥의 상태 판단하기’를 누른다. 아래 시나리오 2의 상태 선택을 해본다. | 단서 후보·근거 회차·작가 상태 선택 | 설정 충돌 검토에서 단서 관리까지 서비스의 범위를 이해한다. |

### 실제 비교 근거

- **3화:** “해주는 열쇠를 꺼내 소형 절단기로 황동 몸통을 잘랐다.” 이어서 두 조각을 배수구에 버리고 사물함 열쇠를 쓸 수 없다고 서술한다.
- **5화:** “열여덟 번 사물함을 열 때 썼던 바로 그 열쇠였다.” 이어서 “서령은 흠집 하나 없는 열쇠를 쥐었다.”라고 서술한다.
- **5화 사용 장면:** “세 번째에는 자물쇠가 돌아갔다.”

### 판단의 분기

| 방문자의 해석 | 선택 | 설명 |
| --- | --- | --- |
| 같은 열쇠라면 수정이 필요하다. | 문제 있음 | 수정해야 할 검토 대상으로 표시한다. 이 선택이 원고를 수정하지는 않는다. |
| 다른 회차의 수리·대체 설명이나 의도를 확인했다. | 문제 아님 | 작가가 맥락을 확인한 뒤 후보를 해제하는 판단을 체험한다. 해당 설명이 실제 존재한다고 데모가 주장하는 것은 아니다. |
| 다른 회차까지 더 확인해야 한다. | 판단 보류 | 근거가 부족할 때도 확정을 강요하지 않는다. |

정해진 정답을 고르게 하지 않는다. 시연자가 선택을 보여줘야 한다면 ‘판단 보류’를 사용하고, “수리나 대체 설명까지 확인한 뒤 결정하겠습니다”라고 설명한다.

### 선택 확인용 추가 행동

‘다른 검토 후보 보기’ → ‘작가 판단’ 탭에서 열쇠 후보가 이동했는지 확인한다. 초기 상태에서 후보 하나를 판단했다면 확인 대기 2개 / 작가 판단 1개가 된다. 새로고침 후에도 판단이 유지된다. 저장소가 차단된 브라우저에서는 화면을 닫기 전까지만 유지된다는 안내가 나온다.

## 시나리오 2 — 단서의 결론은 작가가 정한다

**목적:** 단서 후보를 미회수 오류로 단정하지 않고 관리하는 경험을 보여준다.

1. ‘떡밥의 상태 판단하기’ 또는 왼쪽 ‘떡밥 후보’를 연다.
2. **‘녹색 열쇠의 용도와 은닉 이유’**를 찾는다. 앞서 본 열쇠와 같은 소재라 새 인물이나 사건을 외울 필요가 없다.
3. 후보 설명과 ‘근거 회차’를 확인한다. 표시된 회차는 저장된 언급·관계 근거가 있는 범위이며, 모든 등장 회차를 보장하는 목록은 아니다.
4. 작가 판단을 **‘진행 중’**으로 바꾼다.
5. 더 살펴보고 싶다면 ‘관계 지도에서 확인’을 누른다.

**발표 문장:** “단서가 한동안 나오지 않는다고 곧바로 미회수 오류는 아닙니다. 아직 진행 중인지, 회수했는지, 의도적으로 남겼는지 작가가 정합니다.”

**예상 결과:** 상태 표시가 ‘진행 중’으로 바뀌고 이 브라우저에 저장된다. 원고나 AI 후보 설명은 바뀌지 않는다. 다른 방문자의 판단에는 영향을 주지 않는다.

## 시나리오 3 — 근거가 있어도 결론을 유보할 수 있다

**목적:** 명확해 보이는 충돌만 보여주는 데서 벗어나, 불확실한 후보를 다루는 방식을 보여준다. 기본 3분 체험 이후 자유 탐색에 사용한다.

1. ‘다른 검토 후보 보기’ 또는 ‘검토 결과’를 연다.
2. 확인 대기 목록에서 **‘금고 개방 계약과 민규백의 일방적 취소 요구’**를 선택한다.
3. 계약 정황과 취소 요구의 원문을 읽는다.
4. 민규백에게 취소 권한이 있는지 현재 근거만으로 확정하기 어렵다는 설명을 확인한다.
5. ‘판단 보류’를 선택한다.

**발표 문장:** “이 후보는 계약과 취소 요구를 연결해 찾았습니다. 하지만 취소 권한까지 확인되지 않아 오류라고 단정할 수 없습니다. 작가가 확인할 지점을 남기는 것도 검토의 일부입니다.”

**예상 결과:** 원문 근거와 불확실한 부분을 구분하고, 해당 후보를 보류 상태로 저장한다. 계약 관계가 있다는 것 자체를 오류라고 설명하지 않는다.

## 선택 체험 — 새 문장을 실제 AI로 검토하기

**진행 조건:** 화면에서 AI 연결이 준비되어 있고 남은 이용 횟수가 있을 때만 진행한다. 연결 여부는 시연 직전 확인한다. 기본 시나리오의 완주에 이 단계가 필요하지 않다.

1. ‘새 문장으로 실시간 분석’ 또는 왼쪽 ‘분석’을 연다.
2. ‘예문 넣기’를 누른다. 다음 문장과 기준 범위 **1화부터 3화까지**가 설정된다.

   > 윤해주는 온전한 녹색 황동 열쇠를 주머니에서 꺼내 사물함을 열었다.

3. 이 문장을 **3화 이후 추가하려는 문장**이라고 설명한다. 필요하면 방문자가 직접 문장을 바꾼다.
4. ‘GPT로 검토하기’를 누른다.
5. 반환된 판정·설명·원문 근거를 읽고 ‘이 회차 원고 열기’로 확인한다.

**관찰 목표:** 3화의 열쇠 파손 근거를 찾아 새 문장과 비교하는지 확인한다. 응답 문구나 ‘충돌 후보’ 판정이 반드시 나온다고 약속하지 않는다. 근거 부족·다른 판정이 나오면 실제 응답과 근거를 그대로 설명한다.

**발표 문장:** “앞에서는 저장된 실제 분석 결과를 살펴봤습니다. 이번에는 입력한 문장을 서버에서 새로 분석합니다.”

### 연결 실패·응답 지연 때

- 연결 준비 중이거나 이용 한도가 끝났다면 새 요청을 진행하지 않고 기본 샘플 체험으로 돌아간다.
- 응답이 지연되면 “실시간 요청은 기다리는 중이고, 저장된 원문과 관계는 계속 살펴볼 수 있습니다”라고 설명한다.
- 실패한 요청에 저장된 결과를 끼워 넣거나 실시간 성공처럼 설명하지 않는다.
- 임의로 이용 횟수를 초기화하지 않는다. ‘체험 판단 초기화’는 AI 이용 한도를 초기화하지 않는다.

## 발표자가 바로 읽을 수 있는 짧은 대본

> 긴 소설을 쓰다 보면 앞 회차에서 바꾼 설정을 뒤에서 놓칠 수 있습니다. 스토리 가드는 검토할 부분을 찾아 원문 근거와 함께 보여줍니다.
>
> 이 샘플에서는 3화에서 열쇠를 잘라 버렸는데, 5화에서 같은 열쇠가 온전한 상태로 다시 등장합니다. 실제로 자물쇠를 여는 장면도 있습니다. 원문을 눌러 맥락을 확인할 수 있습니다.
>
> 그렇다고 AI가 바로 오류라고 결정하지는 않습니다. 수리나 대체 설명이 다른 곳에 있을 수 있기 때문에, 저는 우선 판단 보류로 남기겠습니다.
>
> 이 후보와 관련된 인물·사건은 관계 지도에서 이어서 볼 수 있습니다. 열쇠에 얽힌 단서는 아직 진행 중인지, 회수했는지 작가가 관리합니다.
>
> 스토리 가드는 작가가 원문을 더 쉽게 확인하고 판단하도록 돕는 도구입니다. 지금 본 것은 저장된 실제 분석 결과이며, 새 문장을 직접 입력하는 실시간 분석은 별도로 체험할 수 있습니다.

## 처음 방문한 사람에게 줄 과제와 성공 기준

화면 안내만으로 이해하는지 확인할 때는 위 발표 대본을 먼저 읽어주지 않는다. 아래 과제만 전달한다.

> “열쇠에 관한 검토 후보가 타당한지 살펴보고, 작가의 입장에서 판단 하나를 남겨 주세요. 이후 관련 단서의 상태도 하나 정해 주세요.”

| 관찰 항목 | 성공 기준 |
| --- | --- |
| 서비스 이해 | 사용자가 ‘긴 원고의 설정·단서를 근거로 검토하는 도구’라고 자기 말로 설명한다. |
| 근거 확인 | 3화와 5화의 차이를 찾아 설명하고 전체 원문을 한 번 연다. |
| 판단 권한 | AI 후보가 확정 오류가 아니라는 것을 이해하고 판단을 남긴다. |
| 체험 범위 | 저장된 분석 탐색과 새 문장 실시간 분석을 구분한다. |
| 탐색 연결 | 판단 후 관계 또는 떡밥 화면으로 스스로 이동한다. |

진행자는 걸린 시간, 멈춘 위치, 도움을 요청한 지점과 잘못 이해한 말을 기록한다. 목표는 기본 흐름 약 3분이며, 판단의 정답 여부로 평가하지 않는다. 현재는 시나리오를 작성한 상태로, 외부 사용자의 이해도 검증을 완료했다는 뜻은 아니다.

## 시연 전 확인

- 자신의 시연 브라우저에서 판단을 초기화하고 첫 화면을 연다.
- 두 회차 인용문, 원문 이동·복귀, 판단 저장, 관계 스크롤을 확인한다.
- 기본 체험은 AI 미연결 상태에서도 완주할 수 있어야 한다.
- 실시간 시연을 포함할 때만 연결 상태·남은 횟수·실제 응답을 별도로 확인한다.
- 공개 URL에서 실행할 때도 처음 방문한 브라우저로 같은 흐름을 확인한다. 로컬 성공을 공개 배포 성공으로 간주하지 않는다.
