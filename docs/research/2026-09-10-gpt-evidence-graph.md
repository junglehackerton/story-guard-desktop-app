# GPT 근거 관계 지도 구현·검증

2026-09-10. 이전의 GPT 설정 충돌 검토에 인물·아이템·규칙·장소 등의 관계 추출을 연결했다. 로컬 Qwen3 임베딩과 Chroma 검색은 유지하며 같은 GPT 요청에서 이슈와 그래프를 함께 받는다. 별도 검색 AI 모델이나 팀 API 키는 추가하지 않았다.

## 사용

작품 선택 → 모델 및 추론 강도 선택 → 원문 전송 동의 → 이 작품 GPT 분석.

결과 화면에서 ‘전체 관계’를 선택하고 그래프의 ‘인물·설정 선택’으로 유나 등을 선택하면, 오른쪽에 연결된 관계가 표시된다. ‘원문 근거 보기’를 펼쳐 실제 원고를 확인한다. 노드를 직접 선택하는 기존 방식도 유지한다. 모든 관계는 AI 추출 후보이며 작가가 확정한 사실로 표시하지 않는다.

## 검증 방식

- 응답의 각 엔티티·관계는 청크 ID와 정확한 인용문을 필수로 포함한다. 인용이 전달된 청크의 실제 부분 문자열인지 검사한다.
- 존재하지 않는 연결 대상, 잘못된 근거, 누락된 그래프 배열은 실패 처리한다.
- 해당 청크를 인용한 관계만 반영하고, 앞서 추출한 이름을 다음 요청에 전달한다. 동일 유형·이름과 동일 방향·관계 문구는 병합한다.
- 전체 분석이 성공하고 원고 스냅샷이 유지될 때만 그래프·회차 출처·이슈를 한 트랜잭션에서 갱신한다. 기존 이슈의 작가 판단은 보존한다. 재분석 시 같은 노드의 ID를 유지한다.
- GPT 관계의 부정·조건 표현을 일반 관계 이름으로 축약하지 않는다. GPT 자유 문구만으로 시간에 따른 상태 변화를 단정하지 않는다.
- 회차 범위에 노드를 표시할 때 원문 근거도 사용한다. ‘검’ 같은 한 글자 이름이나 요약된 규칙 이름이 단순 이름 검색 때문에 사라지지 않는다.

## 실제 개인 계정 결과

Qwen3-Embedding-0.6B-Q8_0 + Chroma + GPT-5.6-Sol / Low. 가상 원고만 전송했다.

| 실행 | 노드 | 관계 | 충돌 후보 | 시간 |
|---|---:|---:|---:|---:|
| 첫 충돌 사례 | 5 | 8 | 1 | 69.24초 |
| 계약 체결 후 사용 사례 | 6 | 8 | 0 | 64.64초 |
| 이름 일관성·청크 범위 보완 후 충돌 재검증 | 4 | 6 | 1 | 73.30초 |

각 실행은 두 청크에 대해 GPT 요청 2회. 보완 전후 시간이므로 단순 성능 개선 비교로 해석하지 않는다. 최종 재검증에서 규칙 노드의 중복은 없어졌으나 의미가 같은 관계 문구의 완전한 병합은 보장하지 않는다. 계약 체결 사례는 보완 전 실검증이며 보완 후 같은 사례의 GPT 재호출은 하지 않았다.

최종 노드: 유나, 봉인검, 성문, 정식 계약자만 봉인검 사용 가능.
관계 예: 유나 → 봉인검 ‘계약 거절’, 유나 → 봉인검 ‘계약 없이 사용’, 유나 → 성문 ‘봉인검으로 엶’.

브라우저에서 4개 노드·6개 관계를 확인하고, 유나 선택 → 계약 거절 관계의 원문을 실제로 펼쳐 확인했다. 검사한 관계 근거 API는 모두 현재 작품 원문만 반환했다.

기록: `output/validation/gpt-graph-live/results.json`, `recheck.json`.
자동 검증: 백엔드 104개, 프런트엔드 33개 통과. TypeScript/Vite 빌드 통과. 기존 번들 크기 경고가 남아 있다.

## 다음 검증 과제

- 긴 원고 및 예외 규칙을 포함한 정답 데이터셋으로 탐지율·오탐률 측정.
- 별칭, 동명이인, 같은 규칙·관계의 다른 표현을 구분하는 정규화와 작가 확인 UI.
- 관계 유형과 시점을 구조화한 후 시간에 따른 변화 비교. 현재는 미지원임을 화면에 표시한다.
- 짧은 원고 2편에도 약 1분이 걸리므로 요청 크기, 부분 재분석, 실행 전 요청 수 안내가 필요하다.
- 인용문 검증은 출처 존재만 확인한다. 인용이 관계 의미를 충분히 뒷받침하는지는 여전히 모델 오류가 가능하다.
- Windows 및 실제 설치 패키지에서의 실행 검증은 별도다.
