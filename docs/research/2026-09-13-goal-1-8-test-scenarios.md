# Story Guard 1~8 실사용 테스트 시나리오

## 공통 준비

- 최신 `src-tauri/target/release/bundle/macos/Story Guard.app` 또는 Windows 설치본
- 테스트 작품은 새로 만든 `등대 아래의 계약`으로 고정
- 원고 10편: 각 회차에 인물·아이템·규칙·의도적 오류·떡밥을 포함
- 기록 항목: OS, 앱 버전, 원고 회차 수, 선택 모델/추론 강도, 시작·종료 시각, 실패 구간, 재시도 횟수, 스크린샷
- 기존 검증 작품의 결과를 삭제하거나 덮어쓰지 않고 새 프로젝트로 수행

## 시나리오 1 — 새 작가의 10편 첫 분석

**목적:** 깨끗한 사용자 흐름과 신규 프로젝트 E2E 확인

1. 앱 데이터가 없는 새 사용자 상태로 실행한다.
2. 시작 안내에서 새 작품을 만들고 작품명을 입력한다.
3. TXT/Markdown 10편을 한 번에 가져온다.
4. `원고·설정`에서 10편과 설정 메모를 확인한다.
5. 분석 대상 전체를 선택하고 GPT 모델·추론 강도를 선택한다.
6. 분석을 실행하고 진행률·완료 회차를 관찰한다.
7. `검토 결과`, `관계 지도`, `떡밥 후보`를 순서대로 연다.

**기대 결과:** 10편이 모두 등록되고, 분석 완료 후 결과·관계·떡밥 후보가 표시된다. 모든 후보에는 회차와 원문 근거가 있다.

**증거:** 시작/완료 화면, 분석 로그, 결과·그래프·떡밥 화면 캡처.

## 시나리오 2 — 회차 수정·교체

**목적:** 변경된 회차만 증분 분석하고 이전 근거를 섞지 않는지 확인

1. 시나리오 1 완료 상태에서 4화의 인물 이름과 계약 조건을 수정한다.
2. 같은 파일을 4화에 교체 등록한다.
3. 분석 화면에서 변경 감지와 재분석 대상을 확인한다.
4. 재분석을 실행한다.
5. 3화·5화 결과의 근거가 이전 버전으로 유지되는지, 4화 결과가 새 원문으로 바뀌는지 확인한다.

**기대 결과:** 4화만 재분석 큐에 들어가고, 새 버전 청크가 생성된다. 이전 4화 근거가 새 결과에 남지 않는다.

**증거:** 변경 전후 문서 버전, 재분석 대상 목록, 근거 회차·문장 캡처.

## 시나리오 3 — 실패 구간 격리와 재시도

**목적:** GPT 지연/네트워크 오류가 전체 분석을 중단하지 않는지 확인

1. 10편 분석을 시작한다.
2. 테스트 프록시에서 특정 검토 윈도만 timeout 또는 연결 오류를 반환하게 한다.
3. 분석 완료 화면에서 성공·실패 구간을 확인한다.
4. `실패 구간만 재시도`를 실행한다.
5. 성공했던 구간의 GPT 요청이 재발생하지 않는지 확인한다.
6. 재시도 성공 후 전체 결과와 그래프가 병합되는지 확인한다.

**기대 결과:** 실패 구간만 원인·재시도 횟수와 함께 격리된다. 재시도는 실패 구간에만 수행되고 최종 결과가 중복 없이 병합된다.

**증거:** 실패 원인, 재시도 요청 수, 최종 완료 수, 체크포인트 JSON.

## 시나리오 4 — 대량 원고와 중단 후 재개

**목적:** 20편·50편의 처리 시간과 자원 사용, 중단 복구 확인

1. 새 작품에 20편을 등록하고 실제 GPT 분석을 실행한다.
2. 총 시간·편당 시간·CPU·메모리·실패 수를 기록한다.
3. 50편으로 확장하고 분석한다.
4. 분석 중 앱을 강제 종료한다.
5. 앱을 다시 실행하고 같은 작품을 연다.
6. `이어서 분석`을 실행하고 이미 완료된 체크포인트가 재사용되는지 확인한다.

**기대 결과:** 50편 전체를 처음부터 다시 요청하지 않는다. 완료 구간은 재사용되고 중단된 구간만 재개된다. 앱이 버벅이더라도 원본과 작가 판단은 손상되지 않는다.

**증거:** 20/50편 시간·자원 표, 중단 전후 진행률, 재사용/신규 요청 수.

## 시나리오 5 — 원문 근거와 강조 표시

**목적:** AI 결과가 실제 원문과 일치하는지 확인

1. 검토 결과에서 설정 충돌 후보 하나를 연다.
2. 근거 회차를 클릭하고 원문을 연다.
3. 강조된 문장이 결과 인용문과 글자 단위로 일치하는지 확인한다.
4. 다른 회차의 근거도 열어 위치와 문맥을 확인한다.
5. 원문에 없는 문장을 인용한 후보가 있는지 검색한다.

**기대 결과:** 근거 패널의 회차·문장·위치가 실제 원문과 일치한다. 불일치 후보는 결과로 확정되지 않고 검토 필요 상태로 남는다.

**증거:** 결과 카드와 강조된 원문을 함께 찍은 캡처.

## 시나리오 6 — 관계 그래프 상호작용

**목적:** 복잡한 관계를 읽고 문제 관계를 찾을 수 있는지 확인

1. `관계 지도`에서 `전체 관계`를 선택한다.
2. `핵심 관계`, `점검 필요`로 전환한다.
3. 고립 후보·끊긴 끝점·충돌 관계가 시각적으로 구분되는지 확인한다.
4. 노드를 선택하고 관계 선을 선택한다.
5. 오른쪽 근거 패널이 같은 대상·회차를 보여주는지 확인한다.
6. 트랙패드 핀치 확대·축소와 두 손가락 이동을 수행한다.
7. 창을 760×720까지 줄였다가 넓히고 `화면에 맞춤`을 누른다.

**기대 결과:** 필터 전환 때 그래프가 사라지거나 겹치지 않는다. 선택한 관계와 근거가 동기화되고, 확대·이동·맞춤 후에도 노드가 보인다.

**증거:** 각 필터 화면, 선택 관계·근거 패널, 확대율, 최소 창 크기 캡처.

## 시나리오 7 — 깨끗한 설치와 인증 유지

**목적:** 처음 설치한 사용자와 재방문 사용자의 경로 확인

1. 앱 데이터·캐시가 없는 환경에서 처음 실행한다.
2. 시작 안내 → 모델 준비 → GPT 연결 → 첫 작품 생성을 순서대로 수행한다.
3. 앱을 종료하고 다시 실행한다.
4. 저장된 작품과 GPT 연결 상태를 확인한다.

**기대 결과:** 첫 실행은 안내 화면에서 시작하고, 재실행은 저장된 작품 화면으로 진입한다. 인증 상태와 로컬 원고가 유지된다.

**증거:** 첫 실행·재실행 화면, 연결 상태, 작품 목록.

## 시나리오 8 — 중복 실행과 비정상 종료

**목적:** 앱 안정성과 단일 인스턴스 확인

1. 앱을 실행한 상태에서 앱 아이콘을 다시 실행한다.
2. 두 번째 창/프로세스가 생성되는지 확인한다.
3. 분석 중 강제 종료하고 재실행한다.
4. 복구 후 같은 작품에서 결과·체크포인트·작가 판단을 확인한다.

**기대 결과:** 두 번째 실행은 기존 인스턴스로 전달되거나 차단된다. 강제 종료 후 원고·결과·판단이 손실되지 않고 이어서 분석할 수 있다.

**증거:** 프로세스 목록, 재실행 화면, 복구 전후 결과 비교.

## 판정 규칙

- 모든 기대 결과를 충족하고 증거 파일이 있으면 `통과`
- 한 단계라도 실패하면 전체를 재실행하지 말고 실패 시나리오와 구간만 격리한다.
- 실패 기록에는 원인 분류(`입력 형식`, `provider/네트워크`, `앱/sidecar`, `근거 불일치`, `UI`)와 재현 절차를 반드시 남긴다.
- 네이티브 그래프 입력 결과는 `output/validation/goal-1-8-20260913/native-gate-status-20260913.json`에 추가한다.
