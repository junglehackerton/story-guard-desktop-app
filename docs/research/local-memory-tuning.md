# 로컬 임베딩 메모리 절감 검증

EmbeddingGemma는 모델을 처음 로드할 때 가중치와 임시 배치가 함께 올라가므로 피크 메모리가 발생한다. 10편·10만 자 로컬 통합 측정에서 기존 설정은 분석 완료·실패 0을 기록했지만 프로세스 RSS 피크가 약 2.18GB였다.

현재 적용한 안전한 완화책은 다음과 같다.

- 기본 dtype은 `float32`로 유지해 정확도와 CPU 호환성을 우선한다.
- `STORY_GUARD_GEMMA_DTYPE=float16` 또는 `STORY_GUARD_LOW_MEMORY=1`을 명시한 경우에만 MPS·CUDA에서 `float16`을 사용한다. 기기별 속도와 검색 품질을 확인한 뒤 기본값을 바꾼다.
- 임베딩 배치가 메모리 오류를 내면 배치를 8→4→2→1로 줄여 해당 작업만 재시도한다.
- 모델 워커는 프로세스 단위로 격리해 앱 종료 시 함께 정리한다.

이번 실행에서는 자동 dtype을 시험했을 때 분석 시간이 40.685초에서 54.539초로 늘었다. RSS 절감량은 해당 실행에서 별도 계측이 완료되지 않았으므로, `float16`을 기본값으로 채택하지 않는다. 다음 측정에서는 동일 원고·동일 청크·동일 검색 질의를 고정하고 RSS, p95 처리 시간, 검색 상위 결과 일치율을 함께 비교한다.
