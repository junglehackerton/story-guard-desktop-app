# 장편 원고 분석 성능·복구 기록

이 문서는 Story Guard를 실제 장편 원고에 적용하면서 발견한 지연·실패 문제와 개선 결과를 공개 가능한 형태로 정리한 기록입니다. 측정값은 특정 Mac과 GPT 모델에서 얻은 검증 결과이며 모든 장치·원고에서 보장되는 시간은 아닙니다.

## 처음 확인한 문제

- 10편 이상을 한 번에 분석하면 GPT 응답 지연이 누적되어 전체 작업이 timeout으로 끝났습니다.
- 한 구간의 provider 오류가 전체 분석 실패처럼 보였고, 이미 완료된 구간도 다시 요청될 위험이 있었습니다.
- 원고를 교체한 뒤 이전 버전의 청크·근거가 새 결과에 섞일 가능성이 있었습니다.
- 앱을 분석 중 종료하면 진행률과 작가 판단을 잃을 수 있었습니다.
- 큰 그래프를 한 번에 그리면 노드 겹침과 이동 불능으로 근거를 확인하기 어려웠습니다.

## 적용한 개선

1. 원고를 청크와 검토 윈도로 나누고 각 윈도에 체크포인트를 저장했습니다.
2. timeout·네트워크·provider 오류를 구간 단위로 격리하고 원인·재시도 횟수를 기록했습니다.
3. 지수 백오프와 제한된 재시도를 적용해 실패한 윈도만 다시 요청했습니다.
4. 완료된 체크포인트는 재사용하고 변경된 문서 버전의 청크만 재생성했습니다.
5. 중단·재시작 시 성공 결과와 작가의 확정/무시 판단을 보존하도록 복구 경로를 분리했습니다.
6. 그래프는 연결 컴포넌트별 자동 배치, 문제 관계 필터, 고립·끊긴 끝점 표시, 원문 근거 패널을 사용합니다.

## 실제 provider 측정

| 실행 | 결과 | 시간 | 요청/실패 | 비고 |
|---|---:|---:|---:|---|
| 17개 검토 윈도 | 17/17 | 기록된 재시도 후 완료 | 최초 timeout 2개 → 실패 2개만 재요청 | 성공 15개 재사용 |
| 기존 기록의 “실제 GPT 20편” | 20/20 | 638.02초 | 21회 요청, 실패 0 | **주의: 전체 원고 2,355자(회차 평균 118자)인 축소 픽스처라 실제 웹소설 부하 근거가 아님** |
| 기존 기록의 “실제 GPT 50편 증분” | 50/50 | 808.53초 | 신규 31회 요청, 실패 0 | **주의: 장편 분량·실패율을 대표하지 않는 축소 픽스처** |

기존 기록의 CPU 시간은 user 42.41초/system 5.48초로 기록되었습니다. GPT 대기 시간은 CPU 사용량과 별개이며 모델·네트워크·원고 길이에 따라 달라집니다. 다만 해당 20편·50편 파일은 실제 웹소설 길이가 아니라 축소 픽스처였으므로, 완료 시간이나 실패율을 장편 사용자 환경으로 해석하면 안 됩니다. 회차당 1.5만~2만 자 이상의 장편 코퍼스 검증이 별도로 필요합니다.

초기 macOS 부하 기록에는 `ru_maxrss` 단위를 Linux KiB로 처리해 비현실적인 메모리 수치가 기록된 오류가 있었습니다. `scripts/validation/run_real_gpt_load.py`에서 macOS는 bytes, Linux는 KiB로 정규화하도록 수정했으며, 기존 수치는 메모리 결론에 사용하지 않습니다.

## 실패 시 사용자에게 보이는 동작

- 분석 진행률은 `완료 / 진행 중 / 실패 / 대기` 구간으로 나눠 표시합니다.
- 실패 카드에는 실패 구간, 원인 분류, 마지막 시도 시각, 재시도 버튼을 표시합니다.
- `실패 구간만 재시도`를 누르면 성공 구간에는 provider 요청을 보내지 않습니다.
- 재시도 성공분은 기존 결과에 중복 없이 병합하고, 근거가 새 문서 버전과 일치할 때만 게시합니다.
- 사용자가 취소하면 이미 저장된 체크포인트와 작가 판단은 유지합니다.

## 재현 명령

```bash
# 프런트 회귀
npm test -- --run

# 백엔드 회귀
.venv/bin/python -m pytest -q

# 중단·취소·복구 번들
.venv/bin/python scripts/validation/verify_interruption_bundle.py
.venv/bin/python scripts/validation/verify_recovery_bundle.py

# 오케스트레이션 규모 보조 검증
.venv/bin/python scripts/validation/benchmark_scale_projection.py
```

번들 검증은 실제 GPT 품질을 대신하지 않습니다. 실제 provider 측정은 `output/validation/`에 로컬 증거로 보관하고 공개 저장소에는 이 요약 문서와 재현 가능한 코드만 올립니다.

## 남은 리스크

- GPT 응답 지연이 매우 긴 경우 전체 완료 시간이 길어질 수 있습니다. 회차 범위를 나누고 완료 구간 재사용을 권장합니다.
- 장치 메모리가 작은 경우 로컬 임베딩 모델 준비 시간이 늘어날 수 있습니다.
- 관계 그래프의 트랙패드 핀치·두 손가락 이동은 잠금 해제된 실제 Mac에서 최종 인수해야 합니다.
