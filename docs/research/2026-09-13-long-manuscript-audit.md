# 장편 원고 처리 감사 보고서

작성일: 2026-09-13

이 문서는 “10회가 실제 웹소설 회차보다 짧을 수 있다”는 위험을 기준으로, 로컬 색인·증분 갱신·GPT 검토 분할을 각각 확인한 결과다. 로컬 임베딩 시간, GPT 제공자 시간, 판정 품질은 서로 다른 측정값이므로 합산하지 않는다.

## 실패 구간 진단 보강

provider 연결이 첫 검토 구간부터 끊겨도 작업을 terminal `failed`로 소실하지 않고 `partial`로 보존한다. 분석 응답의 `failed_windows`에는 실패 구간 번호, 원문 청크 ID, 오류 코드, 처리 단계, 시도 횟수, 경과 시간이 포함된다. 따라서 사용자는 실패 원인을 확인한 뒤 같은 실행에서 실패 구간만 재시도할 수 있다. 백엔드 204개 테스트, 프론트엔드 110개 테스트, production build, 데스크톱 검증 스크립트를 통과했다.

## 해석

첫 대량 등록은 장치 성능에 따라 수분이 걸릴 수 있다. 따라서 분석 시작 전에 예상량을 보여주고, 색인·GPT 검토를 체크포인트로 나누며, 취소·재개·실패 구간 재시도를 제공하는 것이 기본 동작이다. 새 회차를 등록하거나 일부 회차를 수정할 때 전체 원고를 다시 임베딩하지 않는다.

모델 파일 크기만으로는 메모리 부담을 판단할 수 없다. 이번 Mac 실측에서 Gemma 워커 RSS는 약 1.66GB, Qwen 워커 RSS는 약 2.27GB였다. Setup 화면은 두 값을 실행 환경 참고치로 안내하고, 검색 품질을 우선할 때 Qwen을 선택하되 메모리가 제한된 기기는 Gemma 또는 회차 범위 분할을 고려하도록 유도한다.

총 100만 자의 GPT 전체 검토는 231구간으로 계산된다. 구간당 15~60초를 적용하면 직렬 기준 약 58~231분이며, 이는 계획용 범위다. 실제 사용자 GPT 계정으로 이 전체 범위를 자동 실행하지 않은 이유는 계정 한도와 비용 때문이다. 현재 실제 GPT는 약 6만 자 10회차의 재개 실행과 증분 변경 시나리오까지 확인했고, 장편 전체 시간·품질은 아직 보장하지 않는다.
