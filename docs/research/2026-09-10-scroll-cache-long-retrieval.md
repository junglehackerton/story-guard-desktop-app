# 그래프 스크롤·요청 재사용·장문 검색 검증

## 화면 수정

증상: 100vh에 overflow:hidden인 앱 안에서 workspace가 스크롤되지 않았고, 그래프 flex 영역은 min-height:0이라 거의 0 높이로 줄었다. canvas 내부 최소 높이와 부모 표시 영역이 달랐다.

workspace에 세로 스크롤을 주고 graph-stage를 최소 610px, 축소되지 않는 flex 영역으로 변경했다. 나머지 패널도 강제로 줄지 않게 했다. 헤더의 ‘관계 지도 보기’ 버튼으로 실제 그래프 영역에 이동하도록 했다. 브라우저에서 버튼과 그래프 선택 컨트롤을 실행했다.

## 요청 재사용

검증된 GPT 응답만 로컬 SQLite의 프로젝트별 캐시에 저장한다. 키에는 전체 프롬프트(현재 원문, 검색 근거, 이름 목록), 모델, 추론 강도, 출력 스키마와 버전이 포함된다. 원문·근거·모델·추론 강도 변경 시 재요청한다. 사용자에게 ‘검증된 결과 재사용’ 선택을 제공하며 해제하면 강제로 새 요청한다. 완료 메시지에 새 요청/재사용 횟수를 표시한다.

같은 프로젝트의 캐시는 최대 500개다. 프로젝트 삭제 시 함께 삭제된다. 재사용된 출력도 구조와 근거를 다시 검증한다. 중단된 작업의 이미 검증된 구간도 조건이 완전히 같으면 재사용한다. 첫 분석의 GPT 응답 속도를 높이는 변경은 아니다.

자동 테스트: 동일 요청 2개 재분석 시 추가 호출 0회, 모델 추론 강도 변경·원문 변경·강제 새 분석 시 다시 호출함을 검증했다. 실제 개인 계정에서의 캐시 전후 시간은 측정하지 않았다. 자동 승인 검토가 원문 재전송에 대한 구체적 승인 부족을 이유로 실측 요청을 거절했으며, 우회 호출하지 않았다.

## 장문 검색 검증

스크립트: `PYTHONPATH="$PWD" .venv/bin/python scripts/validate_long_retrieval.py`

30회차 합성 원고 27,138자, 35청크. 기존 로컬 Qwen3-Embedding-0.6B-Q8_0.gguf + Chroma 사용. 외부 GPT 요청은 없음.

첫 실행에서 645토큰 청크가 n_batch=512 제한에 걸려 실패했다. n_ctx=2048과 맞춰 n_batch/n_ubatch=2048로 수정했다. truncate=False를 유지하여 원문을 조용히 자르지 않는다. 2048토큰을 넘는 입력에 대한 추가 토큰 단위 분할은 별도 과제다.

수정 후 전체 임베딩과 검색 성공:

- 색인 생성 16.01초
- 질문 5개 모두 기대 근거가 검색 상위 4개에 포함됨: Hit@4 5/5
- 질문당 검색 0.040~0.075초
- 1화 규칙, 8화 계약, 15화 편지 운반 조건, 22화 열쇠 조건, 29화 사건을 대상으로 함

기록: `output/validation/long-retrieval/results.json`. 데이터는 반복 배경 문장이 많은 합성 자료다. 이 수치는 실제 장편 소설 정확도, 불필요한 검색 결과 비율, GPT 최종 판단의 정확도를 보장하지 않는다. 다음 평가에는 동명이인·별칭·상충하는 예외·시간 변화 및 사람이 라벨링한 실제 원고가 필요하다.
