# 관계 그래프 하드닝 기록

## 목표

관계 지도를 추출 후보의 나열이 아니라 작가가 **연결 상태와 이상 징후를 빠르게 찾는 근거 지도**로 사용하도록 정리한다.

## 남긴 것과 덜어낸 것

- 남김: 엔티티·관계·회차별 근거·원문 인용·작가 판단·고립 후보
- 덜어냄: 모든 후보를 같은 우선순위로 한 캔버스에 강제 배치하는 방식, 중복 관계 라벨의 동시 표시, 미언급만으로 단절을 추정하는 문구
- 분리: 지도(구조 확인), 오른쪽 패널(관계 후보와 근거 확인), 건강도(점검 범위 요약)

## 현재 동작

1. `핵심 관계`는 신뢰도와 최근성 기준의 연결망을 표시한다.
2. `전체 관계`는 전체 후보를 탐색하되 고립 노드를 연결망 크기에 섞지 않는다.
3. `점검 필요`는 핵심 신뢰도 필터를 우회해 전체 추출 결과에서 약한·미분류·무근거 관계와 회차상 변화·명시적 단절을 남긴다. 연결이 없는 엔티티도 고립 후보로 보존한다.
4. 건강도는 연결, 고립 후보, 근거 부족, 미분류, 충돌, 변화, 명시적 단절, 끊긴 끝점을 별도 수치로 보여 준다.
5. 선은 일반 관계, 근거 부족, 충돌, 회차 변화, 명시적 단절을 각각 다른 색·선 형태로 표시한다.
6. 캔버스 위 범례에 각 선의 의미를 문구와 형태로 함께 표시한다.
7. 같은 두 대상을 잇는 여러 관계는 캔버스에서 대표 라벨만 표시하고, 전체 후보와 원문은 오른쪽 목록에서 유지한다.
8. 자동 배치는 연결 요소별 중심-계층형 배치 후 카드 충돌을 해소한다. 일반적인 그래프는 최소 46% 확대를 유지해 지나치게 작아지지 않게 한다. 복잡한 망은 레이어 순서를 상·하 방향으로 반복 바리센터 정렬해 선 교차를 줄인다.
9. 회차 타임라인은 이름이 아니라 엔티티 ID로 연결해 동명이인으로 인한 잘못된 병합을 줄인다.

## 검증

- 프론트엔드 Vitest: 55개 통과
- 백엔드 pytest: 140개 통과
- TypeScript/Vite production build: 통과
- macOS Tauri `.app` 번들: 최신 소스와 사이드카로 생성
- macOS 앱 실검증: 기존 번들에서 16 nodes·29/29 links, 46% 확대, `점검 필요` 선택 시 고립 후보 1개 표시를 확인했다. 최신 번들은 컴퓨터 잠금으로 마지막 변화 선 스타일 캡처가 보류됐다.

## 해석 규칙

후속 회차에 관계가 단순히 등장하지 않은 것은 단절 확정이 아니다. `단절`, `해제`, `결별`, `종료`, `더 이상` 같은 원문 표현이 관계 유형에 포함될 때만 명시적 단절로 표시한다. 모든 후보는 AI 추출 후보이며 작가가 원문을 확인해 판단한다.

## 남은 실증 과제

- 명시적 단절·관계 변화가 포함된 실제 다회차 원고를 macOS 앱에서 재분석해 선 스타일과 회차 패널을 확인한다.

## 2026-09-11 분석 입력 연결 보완

- 작가가 입력한 설정 메모가 실제 분석 프롬프트에 전달되도록 연결했다.
- `confirmed`는 `확정 설정(충돌 판정 기준)`으로, `draft`는 `구상 메모(확정 아님, 참고만)`으로 표시해 모델이 작가의 확정 판단과 아이디어를 혼동하지 않게 했다.
- 메모가 없는 경우에도 모델에 원고 직접 근거만 사용하라는 경계를 명시한다.
- 로컬 LLM과 GPT 분석 모두 동일한 경계를 사용하며, 메모 본문은 길이를 제한해 원고 근거보다 우선하지 않도록 했다.
- GPT 프롬프트 포함 여부를 회귀 테스트로 고정했다.

## 중간 회차 공백 후보

- 같은 엔티티 쌍의 관계가 앞뒤 회차에 관찰되고 그 사이 회차에는 근거가 없으면 후속 관찰을 `gap`으로 표시한다.
- `gap`은 관계 단절이나 오류가 아니다. 건강도와 그래프에서는 확인 필요 대상으로만 표시하고, 원문 패널에서 작가가 판단한다.
- 명시적 단절·관계 유형 변화와 우선순위를 분리해 단절 표현이 있으면 `explicit_break`, 유형이 바뀌면 `changed`, 그 외 중간 공백은 `gap`으로 남긴다.

실제 사용자 연결 GPT의 합성 관계 설명 검증 스크립트는 현재 로컬 자격 증명 저장소에 연결 상태가 없어 실행되지 않았다(`먼저 ChatGPT 계정을 연결해 주세요`). 따라서 이번 결과는 프롬프트·저장·레이아웃 자동 검증까지이며, 실제 GPT 응답의 관계 설명 정확도는 미검증으로 남긴다.
- 동명이인·별칭·관계 방향 전환이 포함된 정답 데이터셋으로 정밀도와 누락률을 측정한다.
- Windows 패키지에서 동일한 레이아웃·필터·근거 패널 동작을 확인한다.

### 계층형 자동 배치 보완

방사형 링은 다수의 자식과 교차 관계가 중앙에 겹쳐 작가가 흐름을 따라가기 어려웠다. 연결 요소마다 차수가 높은 대상을 시작점으로 잡고, 관계 홉을 위에서 아래로 배치하는 계층형 레이아웃으로 변경했다. 같은 홉의 노드는 이미 배치된 부모의 평균 순서(바리센터)를 기준으로 정렬해 공통 부모 주변에 모이며, 독립 연결 요소는 균형 그리드로 패킹한다. 대표선 집계·상태 색상·근거 패널은 유지되므로 배치는 읽기 순서만 개선하고 분석 후보를 삭제하지 않는다.

검증: 관계 레이아웃·GraphView 회귀 13개 통과, TypeScript/Vite production build 통과.

점검 필요 상태가 있으면 캔버스 상단에 충돌·단절·공백·고립 수를 요약하는 경고 스트립을 함께 표시한다. 끝점 누락 관계가 있는 경우 스트립에서 바로 상세 목록을 열 수 있어 건강도 숫자를 찾아다니지 않아도 된다.

### 2026-09-11 교차 감소 자동 배치

단일 하향 정렬만으로는 여러 부모를 공유하거나 먼 레이어를 가로지르는 관계에서 선이 교차할 수 있었다. 각 레이어의 노드를 이전·다음 레이어 이웃의 바리센터로 네 차례 번갈아 재정렬하고, 차수와 ID를 보조 키로 사용해 입력 순서와 무관한 결과를 유지한다. 그래프 의미·후보·근거 데이터는 그대로 보존하며 캔버스 배치만 개선한다.

검증: 관계 레이아웃 5개 통과, TypeScript/Vite production build 통과, `git diff --check` 통과.

관계선에도 ID 기반의 작은 곡률을 넣어 서로 다른 교차 관계가 동일한 직선 위에 포개지지 않게 했다. 곡률은 표시 방식만 바꾸며 방향·후보 수·근거 데이터에는 영향을 주지 않는다.

모델 전환 검증 스크립트의 직접 실행 경로도 보정했다. Qwen → Gemma → Qwen 검사가 임베딩 런타임에서 실패하더라도 traceback만 남기지 않고 `model-switch.json`에 실패 단계와 사용자용 오류를 기록한다. 현재 샌드박스 실행은 llama 컨텍스트 초기화 실패로 통과 처리하지 않았다.

### 브라우저 관계 지도 스모크 · 2026-09-11

임시 backend와 Vite를 연결하고 합성 작품에 유나·봉인검·성문·정식 계약자 4개 엔티티와 4개 관계를 주입했다. 관계 지도에서 `4 nodes`, `4 / 4 links`, 건강도 `연결 대상 4`, `분리된 망 1`을 확인한 뒤 `전체 관계`로 전환했다. 전환 후에도 네 관계 후보와 근거 개수가 유지되고, 캔버스 오류·외부 페이지 스크롤 없이 오른쪽 관계 탐색 목록이 표시됐다. 검증용 프로세스는 종료했다.

### 2026-09-11 배치 안정화 보완

자동 배치 충돌 보정이 한 축으로 최대 40회 노드를 밀어내던 문제를 확인했다. 관계가 많은 그래프에서 이 방식은 캔버스 높이를 불필요하게 키워 `fit` 결과가 축소되고, 노드가 화면 아래로 밀리는 원인이 됐다. 보정 횟수를 8회로 제한하고 좌우 지그재그 위치를 사용하도록 변경했다. 따라서 충돌 회피는 유지하면서도 무한한 세로 확장을 막는다.

회차 변화와 명시적 단절 수치는 여러 회차에서 같은 두 대상을 반복해서 보고해도 관계 쌍 기준으로 한 번만 집계한다. 건강도 숫자가 이벤트 수가 아니라 작가가 확인해야 할 관계 수를 가리키도록 맞췄다.

관계 근거의 기준이 되는 작품별 설정 메모도 추가했다. 메모는 로컬 SQLite의 `story_settings`에 저장하고 `confirmed`(확정 설정)와 `draft`(구상 메모)를 구분한다. 원고·설정 화면에서 직접 추가·편집·삭제할 수 있으며, 구상 메모를 확정 규칙처럼 취급하지 않는다는 안내를 함께 표시한다.

떡밥 후보에도 로컬 상태 저장을 추가했다. `unreviewed`, `in_progress`, `resolved`, `intentional` 상태를 작가가 선택하며, 후보의 등장 회차와 관계 지도 이동을 함께 제공한다. 단순히 후속 회차에 보이지 않는다는 이유로 자동 실패 처리하지 않는다.

검증: `npm test -- --run src/lib/relationshipLayout.test.ts` 4 passed, `npm run build` passed.

### 2026-09-11 표시·초기 로딩 보완

끊긴 관계 목록의 항목을 선택하면 캔버스 밖 관계도 오른쪽 근거 패널에서 확인하도록 연결했다. 누락된 엔티티 이름은 `알 수 없는 대상 #ID`로 표시해 빈 값으로 오해하지 않게 했다. 관계 지도 모듈은 지연 로딩으로 분리해 첫 번들을 228KB로 줄였고, 그래프 준비 중 공통 아이보리·청록 상태를 표시한다. 프론트 테스트·Vite 빌드·macOS `.app` 재빌드를 다시 통과했다.

필터 단계에서도 `전체 관계`와 `점검 필요` 모드에 끝점 누락 관계를 보존한다. 따라서 백엔드가 반환한 끊긴 관계가 캔버스에서 안전하게 제외되더라도 건강도와 원인 확인 목록에서는 실제로 확인된다.

### 13:06 자동 배치 간격 보정

일반적인 스토리 관계 컴포넌트의 방사형 링 반경을 줄여 Cytoscape가 과도하게 축소되지 않도록 했다. 36개를 넘는 대형 컴포넌트는 기존 간격을 유지해 카드 충돌을 피하고, 작은 컴포넌트만 촘촘하게 배치한다. 모델 파일 준비 상태의 UI 문구도 실제 추론 성공을 의미하지 않도록 `로컬 AI 런타임`, `모델 폴더 접근`, `첫 분석에서 실제 실행 환경 확인`으로 정리했다.

### 13:09 분리된 관계망 수 표시

건강도에 `분리된 망` 수를 추가했다. 연결된 엔티티만 대상으로 컴포넌트를 계산하고, 고립 엔티티·끝점 누락 관계는 별도 지표로 유지한다. 이제 전체 관계 화면에서 하나의 연결망인지 여러 섬으로 분리됐는지 즉시 구분할 수 있다.

### 13:12 실제 GPT 관계 설명 재검증 시도

합성 2회차 관계 설명 검증 스크립트를 앱과 동일한 `~/.story-guard` 자격 증명 경로로 실행했으나, 현재 저장소에 연결 토큰이 없어 `먼저 ChatGPT 계정을 연결해 주세요.`에서 종료됐다. 따라서 실제 GPT 응답의 관계 설명 품질은 계속 미검증으로 남긴다. 목업 성공으로 대체하지 않는다.

### 13:18 공통 컴포넌트 계산 유틸리티

프론트엔드의 연결 컴포넌트 계산을 `countConnectedComponents`로 추출하고, 끝점 누락·자기 연결·고립 엔티티를 제외하는 규칙을 단일 유틸리티와 회귀 테스트로 고정했다. GraphView는 서버 지표가 없는 오래된 payload에서도 같은 계산을 사용한다.

### 13:26 모호한 별칭 연결 보호

LLM이 여러 엔티티에 동일한 별칭을 부여한 경우 이름 인덱스가 첫 번째 엔티티를 가리키던 동작을 제거했다. 충돌한 별칭은 모호한 이름으로 기록하고 GPT 관계 저장에서 제외한다. 작가가 원문으로 대상을 특정하기 전까지 근거 없는 선을 그리지 않는 보수적 처리이며, `test_analyzer_does_not_guess_when_alias_resolves_to_multiple_entities` 회귀 테스트로 고정했다.

타임라인·관계 변화 계산도 동일한 공통 인덱스를 사용해 모호한 별칭 이벤트를 변화나 공백으로 잘못 집계하지 않는다. 저장소 회귀 테스트로 관계 설명과 회차 상태가 함께 보수적으로 처리되는지 확인했다.

### 13:40 동일 대상 쌍의 선 겹침 완화

캔버스에는 동일한 두 엔티티 사이의 관계 후보를 대표선 하나로 합쳐 표시한다. 후보가 여러 개면 선 라벨에 `· N개`를 붙이고, 충돌·변화·공백·명시적 단절 중 가장 주의가 필요한 상태를 대표선에 반영한다. 개별 후보와 원문 근거는 오른쪽 관계 설명 패널의 `같은 대상의 다른 관계 후보`에서 계속 전환할 수 있다. 이로써 전체 관계 보기에서 모델·회차별 후보가 선을 중복으로 그려 가독성을 해치는 문제를 줄이면서 분석 정보는 버리지 않는다.

검증: 프론트엔드 Vitest 49개 통과, TypeScript/Vite production build 통과, `git diff --check` 통과.

관계 건강도 헤더에는 여러 지표를 읽기 전에 `안정`·`확인 필요`·`주의 필요`의 종합 상태를 함께 표시한다. 명시적 단절·충돌·끊긴 끝점은 주의 필요로, 고립·근거 부족·중간 공백은 확인 필요로 우선순위를 올린다.

### 13:45 양방향 관계 해석 보완

동일 대상 쌍에 서로 반대 방향의 관계 후보가 함께 있으면 대표선에 양쪽 화살표를 표시한다. 대표선 하나로 겹침은 줄이되, 방향성 정보는 숨기지 않는다. 개별 방향 후보와 근거는 오른쪽 패널에서 비교할 수 있다.

### 13:46 현재 범위 건강도 문구 보완

필터나 회차 범위가 바뀐 뒤에도 서버 전체 그래프의 요약 문구가 남지 않도록, 건강도 설명 앞에 현재 표시 중인 대상·관계 후보 수를 동적으로 붙인다. 따라서 전체 관계와 부분 범위의 상태를 같은 숫자로 오해하지 않는다. 최신 프론트엔드 빌드와 macOS 앱 번들에 반영했다.

### 13:49 연결 중심성 시각화

노드 크기와 불투명도를 고정값으로 두지 않고 현재 표시 범위의 연결 수와 엔티티 상태에 따라 계산한다. 연결이 많은 핵심 인물·규칙은 더 눈에 띄고, 휴면·소멸 후보는 낮은 불투명도로 표시되어 관계망의 중심과 주변 후보를 빠르게 구분할 수 있다. 자동 배치 간격은 노드 카드 간 최소 간격 검사를 계속 적용한다.

### 13:52 노드 중심성 시각 검증 고정

노드 강조 계산(`entityVisual`)을 공개 유틸리티로 분리하고, 연결도가 높을수록 크기가 증가하며 휴면 상태는 투명도가 낮아지는 규칙을 회귀 테스트로 고정했다. 최신 macOS `.app`에도 반영했다.

### 13:55 관계 술어 정규화

GPT가 같은 관계를 앞뒤 공백·연속 공백·유니코드 변형으로 반환해도 NFC 정규화와 공백 정리 후 동일 술어로 저장한다. 병렬 후보 집계가 표기 차이 때문에 쪼개지지 않으며, 원문 근거와 설명은 각 주장에 그대로 보존한다. 회귀 테스트를 추가했고 백엔드 전체 138개 테스트가 통과했다.

### 13:57 건강도 우선순위 회귀 검증

관계 건강도 종합 상태 계산을 `graphHealthLevel` 순수 함수로 분리했다. 명시적 단절·충돌·끊긴 끝점은 `주의 필요`, 중간 공백·근거 부족·고립 후보는 `확인 필요`, 이상이 없으면 `안정`으로 결정하며 우선순위 회귀 테스트를 추가했다.

### 13:58 관계 라벨 정규화

GPT가 반환한 관계 라벨은 유니코드 NFC 정규화와 앞뒤·연속 공백 정리를 거친 뒤 중복·일반 관계 판정에 사용한다. 같은 의미의 라벨이 공백이나 한글 조합 형태만 달라 캔버스에 중복 선으로 늘어나는 현상을 줄이며, 원문 근거와 후보 목록은 그대로 보존한다. 백엔드 회귀 테스트로 정규화와 키 병합을 확인했다.

### 14:00 필터 범위와 충돌 표시 일치

충돌 관계의 선 색상도 현재 캔버스에 표시된 회차·검색·대상 범위의 관계 후보만으로 계산하도록 맞췄다. 다른 회차의 충돌 정보가 현재 범위에 섞여 선 전체를 경고색으로 칠하던 오판을 줄인다. 건강도와 시각 경고가 같은 표시 범위를 공유한다.

### 14:06 임시 복합 그래프 런타임 검증

실제 backend와 Vite를 별도 로컬 포트에서 실행하고, 임시 합성 작품에 7개 엔티티·6개 관계(병렬 후보·반대 방향·고립 후보·분리 컴포넌트·근거 부족)를 주입해 브라우저에서 확인했다. `전체 관계` 전환 후 7 nodes·6/6 links, 분리된 망 2, 고립 후보 2, 근거 부족 1, 미분류 1, 충돌 1이 표시됐고 캔버스가 축소되거나 깨지지 않았다. 고립 후보 펼치기, 관계 후보 선택, 같은 대상의 다른 후보 전환과 근거 패널 갱신도 동작했다. 검증용 backend·Vite 프로세스는 종료했다.

### 14:12 배포 의존성 보안 점검

npm audit에서 보고된 의존성 취약점을 호환 범위 내에서 갱신했고, 후속 audit에서 취약점 0건을 확인했다. 갱신된 의존성으로 프론트 테스트·production build·Tauri 앱 번들을 다시 생성했다.

### 14:14 Windows sidecar 재현 경로

Windows 팀원이 동일한 Python sidecar를 만들 수 있도록 PowerShell 빌드 스크립트를 추가했다. x86_64 Windows Tauri external binary 이름과 `.exe` 확장자를 명시하며, Mac에서는 PowerShell 실행 검증을 하지 않았다.

### 14:18 범위 밖 타임라인 이슈 표시 차단

회차·검색·대상 필터가 적용된 캔버스는 현재 보이는 관계 쌍에 해당하는 타임라인 변화·중간 공백·명시적 단절만 선 색상과 건강도에 반영한다. 다른 회차의 이슈가 현재 화면의 정상 관계를 경고색으로 오염시키지 않도록 표시 관계 쌍과 이슈 쌍을 교집합으로 제한했다.

### 14:19 초기 오류 복구 문구

초기 로딩에서 브라우저 원문 오류(`Failed to fetch`)가 그대로 노출되던 경로를 사용자용 안내로 바꿨다. 네트워크 연결 실패와 로컬 API 인증 만료는 재실행 방법을 안내하고, 진단 가능한 백엔드 메시지는 보존한다. 앱 번들 재생성 및 프론트 테스트 54개 통과를 확인했다.

### 14:20 복합 망 계층 순서 보정

각 연결 컴포넌트의 같은 홉 노드를 단순 ID·차수 순서로 배치하지 않고, 이미 배치된 부모 노드의 평균 각도를 기준으로 정렬했다. 자식이 부모 주변에 모이도록 해 허브·분기 구조에서 불필요한 선 교차를 줄이고, 최소 카드 간격·결정성·컴포넌트 그리드 패킹 규칙은 유지했다. 관계 배치 회귀 테스트 5개와 프론트 production build, macOS `.app` 재생성을 통과했다.

### 14:22 장편 30회차 검색 검증 재현

`STORY_GUARD_DATA_DIR=/tmp/storyguard-long-check .venv/bin/python scripts/validate_long_retrieval.py`로 30회차·합성 원고·Qwen 임베딩 색인을 시작했다. 610MB GGUF 파일은 존재했지만 현재 실행 환경에서 llama 컨텍스트 생성이 실패해 색인 단계에서 중단됐다. 스크립트는 이제 traceback만 남기지 않고 `output/validation/long-retrieval/results.json`에 `status: failed`, 모델 경로, 실패 단계와 범위를 기록한다. 이는 장편 검색 정확도 통과 증거가 아니며, Metal/CPU 실행이 가능한 Mac 환경에서 같은 명령을 재실행해야 한다.

### 14:24 백엔드 준비 무응답 처리

데스크톱 앱의 `/health/ready` 요청 자체가 멈추면 외부 전체 제한 시간이 적용되지 않던 경로를 수정했다. 각 준비 요청을 남은 제한 시간과 최대 2초 중 더 짧은 시간으로 감싸 sidecar 장애 시 시작 화면이 재시도 상태로 전환되도록 했다. 무응답 시나리오 회귀 테스트를 추가했고 프론트 55개 테스트·desktop verify·macOS 앱 재빌드를 통과했다.

### 14:27 임베딩 메모리 기본값 보정

Qwen GGUF 임베딩 초기화의 기본 문맥을 1,024 토큰, 배치·마이크로배치를 512로 제한했다. 한 청크를 처리하는 임베딩 경로에는 충분한 크기이며, `STORY_GUARD_EMBED_N_CTX`로 256~4,096 범위에서 조정할 수 있다. 30회차 검증을 이 값으로 재실행했지만 현재 환경에서는 Metal·CPU 모두 llama 컨텍스트 생성이 실패했다. 장치가 정상인 Mac 또는 Windows에서 재측정해야 한다.

### 14:34 장편 색인 배치 최적화

Qwen 임베딩 문서 색인은 청크를 최대 16개씩 한 번에 llama.cpp에 전달한다. 모델을 매 청크마다 호출하던 경로보다 긴 원고에서 호출 오버헤드를 줄이고, 배치 크기는 노트북 메모리 한도 안에서 고정한다. 33개 입력에 대한 `16·16·1` 분할 회귀 테스트와 백엔드 전체 140개 테스트를 통과했다.

### 14:36 실제 GPT 관계 설명 검증 기록 보강

사용자 GPT 연결을 사용하는 관계 설명 검증을 실행했으나, 현재 자격 증명이 없어 모델 조회 단계에서 중단됐다. 검증 스크립트가 이 상태를 `live-result.json`에 `stage: connection`으로 기록하도록 수정했다. 실제 모델 응답·관계 추출·원문 인용 검사는 연결된 환경에서만 통과로 판단한다.

### 15:18 끊긴 끝점의 캔버스 표시

관계 후보의 한쪽 엔티티가 현재 작품 목록에 없으면 기존에는 경고 목록에서만 보이고 캔버스에서는 선 자체가 사라졌다. 전체 관계 화면에 `미확인 대상 #ID` 고스트 노드를 추가하고 적갈색 점선으로 연결해, 누락된 등록·추출 문제의 위치를 관계망 안에서 바로 확인할 수 있게 했다. 고스트는 저장 데이터나 엔티티 선택 상태에 쓰지 않으며 오른쪽 끊긴 관계 목록과 연결된다.

### 15:20 고스트 끝점 회귀 테스트

고스트 생성 로직을 순수 함수로 분리하고, 누락된 끝점이 캔버스용 복사본에만 추가되며 원래 표시 그래프와 저장 후보는 변경하지 않는지 회귀 테스트로 고정했다. 프론트엔드 테스트 56개와 TypeScript/Vite production build를 통과했다.

### 15:26 브라우저 고스트 끝점 스모크

임시 작품에 유나·봉인검·성문 관계를 주입한 뒤 장소 유형을 숨겨 현재 표시 범위에서 성문을 누락시켰다. 화면에서 `2 nodes`, `2 / 2 links`, 종합 상태 `주의 필요`, `끊긴 끝점 1`이 함께 표시되고, 캔버스용 관계 설명은 `봉인검 → 알 수 없는 대상 #3`으로 남았다. `끊긴 관계 1개 보기` 진입점도 표시됐다. 실제 브라우저에서 필터 변경 후 경고·근거 목록이 갱신되는 것을 확인했으며, 검증용 backend·Vite 프로세스는 종료했다.

### 15:32 모델 검증 실행 결과 보존

Qwen 하이브리드 검색 심화 검사를 실제 런타임으로 재실행했을 때 현재 환경의 llama 컨텍스트 생성이 실패했다. 새 `scripts/validation/run_structured_check.py` 래퍼로 실행 명령·반환 코드·실패 단계(`embedding_runtime`)·stdout/stderr tail을 `output/validation/retrieval-strategies/fresh-runtime.json`에 기록했다. 런타임 실패를 검색 점수 통과로 대체하지 않으며, 모델이 준비된 Mac/Windows에서 같은 래퍼를 재실행하면 성공 결과를 별도로 남긴다.

### 15:30 관계 이상 범례 보완

건강도 경고 스트립에 근거 부족·미분류 관계·회차 변화도 함께 요약하고, 범례에 `끊긴 끝점` 선 스타일을 추가했다. 수치·선 스타일·진단 목록이 같은 용어를 사용하므로 색상만 기억하지 않아도 문제 연결을 찾을 수 있다. 프론트엔드 테스트 56개와 production build를 재확인했다.

### 15:38 관계 그래프 제품 기준 고정

관계 지도의 목적을 “노드 나열”이 아닌 “문제 관계를 발견하고 원문으로 확인하는 검토 도구”로 명시했다. 근거 이동성·끊긴 끝점 가시성·현재 범위와 건강도의 일치·결정적 자동 배치를 필수 기준으로 남기고, 긴 라벨 도배·임의 엔티티 추정·범위 밖 경고 오염·그래프 안 원고 편집은 제거 대상으로 고정했다. 상세 판정표는 `docs/research/2026-09-11-relationship-graph-product-criteria.md`에 기록했다.

앱 설정에서 EmbeddingGemma를 선택하면 검증 샘플 수치(`152 청크 · 31.95초 · Top-4 29/40`)가 즉시 바뀌어 표시되는 브라우저 스모크를 확인했다. 화면은 이 수치를 어떤 장치의 보장값으로 오해하지 않도록 `검증 샘플 기준`으로 표시한다. Qwen은 현재 장치의 llama 컨텍스트 초기화 실패가 명시적으로 남아 있으며 성공으로 표시하지 않는다.

### 15:42 분리된 관계망 탐색기

건강도에서 분리된 망의 개수만 알려주던 동작을 보완해, 둘 이상의 연결 컴포넌트를 `망 1 · 대상 수 · 관계 수` 선택기로 표시한다. 선택하면 해당 망의 중심성이 가장 높은 대상을 기준으로 자동 초점이 맞춰지고, 고립 엔티티와 끝점 누락 관계는 컴포넌트 수에 포함하지 않는다. `relationshipComponents` 순수 유틸리티와 회귀 테스트를 추가했으며 프론트엔드 58개 테스트·production build를 통과했다.

### 15:52 관계망 선택을 전체 컴포넌트 포커스로 보정

분리된 망 선택기가 중심 노드의 1단계 주변만 보여주던 동작을 수정했다. 이제 `망 N`을 선택하면 해당 연결 컴포넌트의 모든 대상과 관계를 유지한 채 별도 포커스로 표시하며, 선택 대상 주변 보기와 혼동되지 않도록 두 포커스 상태를 분리했다. 컴포넌트 포커스에서는 다른 망의 고스트 끝점이 섞이지 않고 `관계망 전체로`로 원상 복귀한다. TypeScript/Vitest/build를 재확인했다.

### 15:55 컴포넌트 전체 읽기 강조

컴포넌트 전체 보기에서는 중심 대상 선택을 유지하되 주변 노드를 흐리게 만드는 선택 음영을 비활성화했다. 구조 확인 모드에서 연결망 전체가 동일한 가독성으로 남고, 개별 대상 주변 보기에서는 기존의 주변 강조 동작을 유지한다. 프론트엔드 58개 테스트와 production build를 통과했다.

### 15:56 건강도 수치에서 근거로 바로 이동

건강도 스트립의 근거 부족·미분류·충돌·변화·중간 공백·명시적 단절·끊긴 끝점 수치를 버튼으로 바꿨다. 해당 항목이 있으면 첫 관계를 선택해 오른쪽 근거 패널과 원문 이동 경로를 즉시 열고, 없는 항목은 비활성 상태로 유지한다. 키보드 포커스와 상태 문구를 함께 제공하며 프론트엔드 58개 테스트·production build를 통과했다.

### 15:58 집계 대표선과 개별 후보 선택 연결

동일 대상 쌍을 대표선 하나로 그리는 경우에도 대표선 데이터에 모든 후보 관계 ID를 보존하고, 오른쪽 패널·건강도에서 어떤 후보를 선택해도 해당 대표선이 강조되도록 연결했다. 후보 정보는 패널에 남고 캔버스 강조만 대표선으로 합쳐진다. 프론트엔드 58개 테스트와 production build를 통과했다.

### 16:01 관계망 포커스 재렌더링 안정화

컴포넌트 목록과 선택된 컴포넌트를 메모이제이션해, 부모 상태가 바뀌어도 관계 데이터가 같으면 Cytoscape 캔버스를 재생성하지 않도록 했다. 실제 그래프 데이터·필터·자동 배치 리비전이 바뀔 때만 다시 그린다. 포커스 읽기 동작은 유지하면서 불필요한 레이아웃 재계산과 깜빡임을 줄였고 프론트엔드 58개 테스트·production build를 통과했다.

### 16:06 분리 망 제목의 원래 인덱스 유지

컴포넌트를 선택한 뒤 화면이 한 망으로 좁혀져도 제목이 항상 `망 1`로 재계산되던 문제를 수정했다. 전체 관계망 목록의 인덱스를 기준으로 `망 2 전체`처럼 원래 위치를 유지하며, 최신 macOS DMG까지 재생성해 마운트 확인했다.

### 16:08 첫 실행 진입점 정리

프로젝트가 없거나 sidecar가 아직 준비되지 않은 상태에서 빈 관계 지도가 첫 화면으로 열리던 문제를 수정했다. 앱 기본 진입점을 시작 안내로 바꿔 서비스 설명·원고 가져오기·AI 연결 순서를 먼저 안내하고, 작품을 선택한 뒤 관계 지도로 이동하도록 했다. 프론트엔드 테스트·production build와 최신 macOS DMG 마운트 검증을 통과했다.

### 16:16 회차 공백 자동 추론

분석기가 `gap` 또는 `gap_before`를 빠뜨려도 같은 관계의 근거 회차가 1화와 4화처럼 비연속이면 `중간 공백 후보`로 계산한다. 이는 관계 해제나 설정 붕괴로 확정하지 않는 보수적 진단이며, 기존 건강도 경고·선 스타일·근거 선택과 같은 관계 ID를 사용한다. 회차 근거가 없는 일반 관계에는 적용하지 않는다.

### 16:18 깊은 관계망 접기 배치

긴 연쇄형 그래프가 세로로만 늘어나 전체 맞춤 시 썸네일처럼 축소되던 문제를 보완했다. 9단계보다 깊고 18개 대상이 넘는 컴포넌트는 여섯 레벨마다 새 행으로 접어 화면 비율을 유지하고, 허브·분기 구조의 계층 배치는 그대로 유지한다. 순수 배치 회귀 테스트로 30개 연쇄의 높이 상한을 고정했다.

### 16:23 문제 관계만 강조 모드

전체 관계를 숨기지 않으면서 정상 연결의 대비를 낮추는 `문제 관계만 강조` 모드를 추가했다. 충돌·중간 공백·명시적 단절·근거 부족·미분류·끝점 누락·약한 관계 선은 유지하고, 정상 선·노드는 흐리게 표시한다. 데이터 수치와 원문 근거 목록은 같은 범위를 유지하므로 복잡한 그래프에서 이상 연결을 먼저 찾을 수 있다. 프론트엔드 60개 테스트와 production build를 통과했다.

관계 상세 패널이 마지막 관계 언급 이후의 모든 회차를 공백으로 잘못 판단하던 조건을 제거했다. 그래프 건강도와 동일한 회차별 공백 계산기를 사용해 실제 중간 누락만 안내하며, 이후 전개가 아직 작성되지 않은 경우는 단절 후보로 과장하지 않는다.

### 16:28 중간 공백 진단을 캔버스와 통일

건강도 칩은 비연속 회차 재등장을 중간 공백 후보로 계산했지만 그래프 선은 명시적인 `gap` 이벤트만 읽어 같은 관계가 서로 다른 상태로 보일 수 있었다. 캔버스의 `gapPairs`도 `timelinePairsByStatus(graph, "gap")`를 사용하도록 통일해, 모델이 라벨을 빠뜨려도 1화와 4화처럼 비연속 회차에 재등장한 관계가 점선으로 강조된다. 이는 단절·모순 확정이 아닌 작가 확인 후보이며, 프론트엔드 60개·백엔드 140개 테스트로 확인했다.

### 16:31 구체적 술어의 반대 관계 감지

충돌 건강도가 `동행/협력`과 `적대/의심`이라는 두 고정 라벨만 인식하면 GPT가 `계약 체결`, `계약 거절`, `보호함`, `적대`처럼 더 정확한 관계명을 반환했을 때 이상을 놓칠 수 있다. 의미가 양립하기 어려운 긍정·부정 술어 집합을 공통 판정 함수로 추가하고, 관계 건강도·그래프 선·상세 패널이 함께 사용하도록 보완했다. 시간 순서나 예외를 확정하지 않는 후보 표시이며, 반대 술어 3종과 일반 상태 변화 1종 회귀 테스트를 추가했다.

API의 `GraphHealth` 계산도 같은 의미 판정과 비연속 회차 공백 추론을 사용하도록 맞췄다. 따라서 그래프 화면이 자체 계산한 진단과 저장소가 반환하는 건강도 수치가 서로 다른 결과를 내지 않는다. 저장소 회귀 테스트에서 1화·4화 재등장 관계의 공백 수치와 구체적 반대 술어를 확인했다.

### 16:40 전체 관계망 복귀 선택 상태 초기화

분리된 망을 중심 노드로 열어본 뒤 `관계망 전체로`를 눌러도 중심 엔티티 선택이 남아 전체 캔버스가 다시 주변 관계 강조 상태로 흐려질 수 있었다. 전체 망 복귀 시 포커스와 엔티티·관계 선택을 함께 해제하도록 수정해, 전체 관계를 동일한 대비로 다시 읽을 수 있게 했다. 프론트엔드 테스트 61개와 production build를 통과했다.

### 16:45 관계망별 문제 수와 활성 상태 표시

분리된 관계망 선택기가 대상 수와 관계 수만 보여주면 작가는 어느 망부터 확인해야 하는지 다시 캔버스를 열어봐야 했다. 각 망에 근거 부족·미분류·충돌·변화·중간 공백·단절 후보의 관계 수를 합산해 `문제 N`으로 표시하고, 현재 선택한 망은 청록색 활성 상태와 `aria-pressed`로 구분한다. 관계를 숨기지 않고 검토 순서만 빠르게 정할 수 있다.

### 16:52 엔티티 유형별 도형 의미 복원

복잡한 망에서 색상만으로 인물·아이템·규칙·사건을 구분하면 색각 차이나 필터 상태에서 의미를 잃는다. 인물은 원형, 아이템은 둥근 사각형, 규칙은 사각형, 사건은 마름모, 떡밥은 육각형으로 렌더링해 유형과 상태를 동시에 읽을 수 있게 했다. 유형 문구와 색상은 계속 유지해 단일 시각 신호에 의존하지 않는다.

### 18:41 전체 관계망 조밀 배치·문제 선 자동 이동

20개 이상 대상의 계층 간격과 분리 망 사이 여백을 줄여 전체 보기에서 노드가 화면 밖으로 밀리거나 썸네일처럼 축소되는 현상을 완화했다. 카드 충돌 검사는 유지하고, 깊은 연쇄의 접기 배치와 컴포넌트별 포커스도 그대로 둔다.

건강도에서 근거 부족·충돌·단절·중간 공백·끊긴 끝점을 선택하면 오른쪽 근거 패널뿐 아니라 캔버스의 대표선과 양 끝점으로 자동 이동한다. 대표선에 합쳐진 후보를 선택해도 `relationIds`를 통해 같은 선을 강조하므로, 전체 관계에서 문제 위치를 직접 찾아야 하는 부담을 줄였다.

검증: 프론트엔드 64개, 백엔드 145개 테스트 통과, TypeScript/Vite production build 통과, 데스크톱 검증 통과, macOS arm64 DMG 재생성 및 `hdiutil verify` 통과.

오른쪽 관계 후보 목록도 같은 진단 우선순위를 적용한다. 충돌·회차 변화·중간 공백·근거 부족·약한 관계를 먼저 보여주고, 같은 우선순위 안에서는 근거 수와 안정적인 ID 순서를 사용한다. 캔버스에서 발견한 이상을 목록에서 다시 찾는 순서를 줄인다.

### 18:47 관계 범위 전환 시 포커스 초기화

`핵심 관계`·`전체 관계`·`점검 필요` 또는 회차·유형·검색 범위를 바꾸면 이전 컴포넌트 포커스와 고스트 후보 펼침 상태를 초기화한다. 이전 범위의 망만 남아 전체 관계가 깨져 보이는 상태를 방지한다. 범위 전환 후에는 새 그래프 데이터에 맞춰 자동 배치와 건강도 수치를 다시 계산한다.

### 18:49 화면 맞춤과 노드 잘림 보정

작은 관계망에서 가독성 최소 확대값이 `fit()` 결과보다 커지면 상단·하단 노드가 캔버스 밖으로 잘릴 수 있었다. 전체 맞춤 결과를 우선하고 큰 망에만 보수적인 최소 확대값을 적용해, 관계망 전체가 화면 안에 남도록 조정했다. 프론트엔드 64개 테스트·production build·macOS arm64 DMG 재생성을 통과했다.

### 18:54 창 크기 변경 시 외곽 노드 여백 보정

실행 중인 macOS 창에서 맞춤 직후 외곽 노드가 캔버스 경계에 닿아 보일 수 있는 여지를 줄였다. `fit()` 패딩을 일반 망 100px·대형 망 82px로 분리하고, 작은 망의 확대 하한을 24%로 낮춰 창 크기 변경 때 전체 관계망을 우선 보존한다. 그래프 데이터나 근거 후보는 변경하지 않는다.

### 19:00 문제 관계 라벨 우선 노출
