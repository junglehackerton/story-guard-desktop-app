# Story Guard 구현·검증 감사 · 2026-09-11

이 문서는 작업 보드의 완료 조건을 코드·테스트·실행 증거와 대조한 기록이다. `통과`는 현재 저장소에서 직접 확인한 범위만 의미한다.

## 테스트 실행 경로 정리 · 2026-09-13

- 저장소 루트에서 `.venv/bin/pytest -q`를 실행해도 백엔드 패키지를 찾고 임시 데이터 디렉터리를 사용하도록 `pytest.ini`와 `backend/tests/conftest.py`를 추가했다. 실제 사용자 DB를 건드리지 않는 조건에서 백엔드 197개 테스트가 통과했다.
- 프론트엔드 106개 테스트와 production build도 다시 통과했다. 이 변경은 테스트 실행 안정성을 높이는 것이며, 실제 GPT 제공자 품질이나 네이티브 화면 조작을 대신 증명하지 않는다.
- 부분 배치 안내를 정정했다. 완료 구간은 체크포인트로 보존되고 전체 검증이 끝난 뒤 그래프에 게시된다는 실제 동작을 진행 패널·장편 안내·백엔드 상태 메시지에 일치시켰다. 부분 실행 중 기존 게시 그래프를 새 결과로 덮어쓰지 않는다는 경계를 명확히 했다.
- 회차 범위 분석 API를 구현했다. `start_chapter`·`end_chapter`로 선택한 회차만 GPT 검토하고, 범위 밖의 게시 그래프·열린 이슈를 병합 시드로 보존한다. 범위 요청 전달 회귀와 선택 회차만 프롬프트에 포함되는 백엔드 검증을 추가했다. 실제 화면의 범위 선택 UX와 네이티브 장편 E2E는 아직 별도 검증 대상이다.
- 범위 분석 변경을 포함한 macOS arm64 sidecar와 `.app`를 다시 빌드했다. 패키징 backend 복구 검증은 `packaged_backend_ready=true`, 시작 17.01초, GPT 요청 0회, 사용자 데이터 변경 없음으로 통과했다. 네이티브 화면 조작은 Mac 잠금 상태로 미검증이다.

## 후속 복구 번들 재검증 · 2026-09-13

- 패키징된 backend 준비 검증을 다시 실행해 `packaged_backend_ready=true`, 시작 16.79초, 복구 스키마·적응형 분할·제공자 오류 정책 검증 통과를 확인했다. GPT 요청은 0건이며 원본 사용자 데이터는 변경되지 않았다.
- 중단·취소 번들을 다시 실행해 `interrupted_windows_closed=true`, `cancelled_windows_closed=true`, 기존 진행률·모델 추론 강도·체크포인트·작가 판단 보존, 반복 취소 무변경을 확인했다. 패키징 backend 준비 10.57초, GPT 요청은 0건이었다.
- 두 검증 모두 네이티브 macOS 화면 조작은 포함하지 않는다. 현재 Mac 잠금 상태로 인해 설치 후 창 조작과 실제 사용자 GPT 호출은 여전히 미검증이다.
- 200회·회당 6,200자(총 124만 자) 스케일 투영에서는 3,000청크·400검토 구간을 8.348초에 구성·저장했고 실패 구간 없이 완료했다. GPT를 순차 호출할 경우 구간당 15/30/60초 가정에서 약 100/200/400분이므로, 실제 장편은 20구간 단위 실행·캐시 재사용·실패 구간 재시도를 기본 UX로 유지해야 한다. 이 수치는 실제 GPT 지연이나 품질을 측정한 것이 아니다. 결과는 `output/validation/realistic-manuscript-20260912/scale-200-episodes.json`에 보존했다.
- 기존 회차 교체 API에서 재생성 청크의 `project_id`가 0으로 기록될 수 있던 결함을 수정했다. 수정된 원고가 검색·증분 분석에서 누락되지 않는 회귀 테스트를 추가했으며, 백엔드 전체 테스트는 **197개 통과**했다.
- 합성 결함 원고 시나리오도 재실행했다. 인물·아이템·떡밥 엔티티, 관계 3종, 설정 충돌 1건, 2개 이상 원문 근거, 떡밥 후보와 실제 청크 연결을 모두 확인했다(`realistic_story_scenario.py`, 4청크).
- 10회·6.2만 자 증분 검증을 재실행했다. 최초 분석은 20회 GPT 요청, 11회차 추가는 새 구간 5회 요청과 기존 20구간 재사용, 1회차 수정은 변경 구간 1회 요청과 기존 23구간 재사용으로 확인했다. 결과는 `output/validation/realistic-manuscript-20260912/incremental.json`에 보존했다.
- 100회·회당 6,200자 스트레스 검증도 재실행했다. 1,414청크·202검토 구간에서 타임아웃 1건을 주입했지만 실패 구간 0개로 완료했고, 101회차 추가는 새 요청 2회와 기존 201구간 재사용으로 끝났다. 이는 오케스트레이션·체크포인트 검증이며 실제 GPT 지연·판정 품질은 포함하지 않는다.
- 1,000회·회당 6,200자 구조 검증도 완료했다. 620만 자를 15,000청크·2,000검토 구간으로 구성하고 145.391초에 저장했으며 실패 구간은 0개였다. 순차 GPT 호출은 구간당 15/30/60초 가정에서 약 500/1,000/2,000분으로 환산되므로, 이 규모에서는 초기 전체 검토보다 회차별 증분 검토와 명시적 묶음 실행을 기본값으로 안내해야 한다.

## 최신 재검증 기준 · 2026-09-11 19:00

- 관계 지도: 근거 가중 백본 표시와 복잡한 관계망 자동 배치를 포함한 프론트엔드 **64개** 테스트 통과.
- 백엔드 전체 회귀: `backend/tests` **145개** 통과(의존성 DeprecationWarning 1개).
- 전체 빌드: `npm test -- --run`(64개), `npm run build`, `./scripts/verify-desktop.sh`, `git diff --check` 통과.
- macOS arm64 패키지: `output/releases/Story Guard_0.1.0_arm64.dmg` 생성 및 `hdiutil verify` 통과. 현재 해시 `aa8e5f24e0baf35460e9122d219c983f2093f13d485f30f08897a67164041d08`.
- 장편 검색: 30회차·35청크·핵심 질의 5개를 실제 Qwen으로 실행해 `hit@4 = 1.0`을 확인했다. 청크 상한 조정으로 512토큰 초과 오류는 사라졌지만 색인 909.79초, 질의 7.86–26.08초로 측정되어 첫 색인과 Qwen CPU/저사양 경로는 성능 개선 대상으로 남긴다. 결과는 `output/validation/long-retrieval/results.json`에 보존했다.
- 장편 안정화 보정: 한국어 청크 상한을 420자·겹침 56자로 조정하고, 색인 갱신을 문서별 호출에서 16개 청크 배치로 통합했다. 기본 임베딩 컨텍스트는 청크 길이에 맞춰 512토큰, 기본 CPU 스레드는 8개로 설정했으며 `STORY_GUARD_EMBED_N_CTX`·`STORY_GUARD_EMBED_THREADS` 환경변수로 조정할 수 있다. 새 장편 실행도 `hit@4=1.0`을 유지했지만 색인 1,534.29초로 측정되어 Qwen은 정확도 우선 선택지로 유지한다.
- 관계 지도 가독성 보정: 20개 이상 노드의 계층 간격과 분리 망 간격을 줄여 전체 보기에서 축소되는 현상을 완화했고, 건강도 칩에서 관계를 선택하면 해당 선과 양 끝점으로 자동 이동하도록 했다. 모든 관계 후보·끊긴 끝점·고립 후보는 계속 보존한다.
- 외부 환경 항목(Windows 설치, 서명·공증, 실제 100만 자 장편 원고의 GPT 정밀도·총 시간)은 여전히 별도 증거가 필요하다.

- 브라우저 관계 지도 스모크: 임시 backend/Vite에서 4개 엔티티·4개 관계를 연결하고 `전체 관계` 전환 후 관계 후보·근거 목록 유지와 외부 스크롤 없는 화면 구조를 확인했다. 필터로 끝점을 숨긴 고스트 끝점 경로도 `2 nodes`, `2 / 2 links`, `끊긴 끝점 1`, `주의 필요`를 확인했다. 실제 macOS 네이티브 창 조작은 잠금 해제 후 별도 확인이 필요하다.
- 관계 건강도 경고 스트립은 근거 부족·미분류 관계·회차 변화까지 요약하고, 범례는 끊긴 끝점의 적갈색 점선 스타일을 설명한다. 프론트엔드 테스트 58개와 production build를 통과했다.

실제 사용자 GPT 호출은 앱과 동일한 `~/.story-guard` 경로를 읽도록 검증 스크립트를 보정했지만, 현재 연결 토큰이 없어 실행되지 않았다. 실기기 UI 검증도 잠금 상태가 해소된 뒤 같은 합성 원고와 다회차 샘플로 다시 실행한다. 그 전까지는 공개 기능이나 정확도를 확정했다고 표시하지 않는다.

앱 설정 화면에서 임베딩 모델을 Qwen에서 EmbeddingGemma로 전환하는 브라우저 스모크를 추가 확인했다. 선택 직후 `Gemma 로컬 워커 확인 완료 · 152 청크 31.95초 · Top-4 29/40` 근거가 표시되며, 모델 변경 후 인덱스를 다시 준비해야 한다는 안내도 함께 노출된다. Gemma 격리 워커의 품질 측정과 별개로 Qwen은 Metal 장치 기본값을 보정한 뒤 실제 앱 RAG 인덱싱·재시작·삭제 근거 제외 검사를 통과했다.

후속 실행에서는 app-server의 `Reconnecting… waiting for network` 이벤트를 공급자 오류로 즉시 격리해 약 30초 안에 실패 구간을 기록했다. 프론트 production build와 `verify-desktop.sh`도 통과했으며, 실제 GPT 성공 판정은 네트워크가 가능한 환경에서 다시 수행한다.

공급자 연결 장애가 확인되면 남은 검토 창을 반복 요청하지 않고 `deferred`로 보류하도록 회로 차단을 추가했다. 성공 체크포인트는 유지하고 연결 복구 후 실패 구간만 재시도할 수 있다. 백엔드 전체 테스트는 200개로 갱신됐고 sidecar 복구 검증도 재통과했다.

장편 오케스트레이션 회귀도 재실행했다. 10회·회당 20,000자(총 200,000자)는 495청크·55검토 구간에서 시간 초과 1건을 자동 재시도해 실패 0개로 완료했고, 11회차 추가는 신규 5구간만 요청하고 51구간을 재사용했다. 100회·총 620,000자 구조 검증은 1,500청크·200구간을 2.471초에 구성했다. 두 결과 모두 실제 GPT 응답 지연·의미 정확도는 포함하지 않는다.

실제 GPT 검증 도구는 실패한 케이스도 `output/validation/revision-gpt/results.json`에 저장하도록 보완했다. 현재 Luna low 실행은 네트워크 장애로 3회 요청 후 18초에 실패 원인과 케이스를 기록했다.

네트워크 권한 환경에서 같은 검증을 재실행해 실제 `gpt-5.6-luna / low` 응답을 받았다. 충돌 케이스는 44.74초·GPT 요청 2회로 충돌 후보 1개를 기대대로 검출했고, 계약 체결로 해소되는 케이스는 68.87초·요청 4회로 후보 0개를 기대대로 반환했다. 세 번째 케이스는 승인된 총 6회 요청 한도에 도달해 실행하지 못했으며 결과 JSON에 미실행 오류를 남겼다. 이는 합성 2케이스의 의미 판정 통과이며 실제 장편 원고 품질·평균 지연을 보증하지 않는다.

세 번째 무관 내용 혼합 케이스는 케이스 선택 실행으로 별도 검증했다. 38.48초·요청 2회로 무관한 문장을 제외하고 규칙 충돌 후보 1개를 검출해 기대 결과와 일치했다. 세 케이스 모두 실제 GPT 응답으로 통과했지만, 짧은 합성 원고 결과를 장편 정확도로 확대 해석하지 않는다.

실제 10회차·총 약 60,000자 원고로 첫 묶음 장편 E2E를 실행했다. 로컬 색인 뒤 8개 청크를 GPT에 1회 요청해 21.64초에 검증 완료했고, `batch_limit=1`에 따라 나머지 9개 묶음은 요청하지 않고 `deferred`로 보류했다. 전체 작업은 73.9초, 진행률 10%의 `partial` 상태로 체크포인트를 보존했다. 결과 요약은 `output/validation/long-gpt-20260913/README.md`에 남겼으며, 전체 10회차의 GPT 품질·총 소요 시간과는 구분한다.

같은 실제 저장소에서 다음 2묶음을 이어서 실행했다. 46.07초·신규 GPT 요청 2회로 2·3번 구간을 완료하고 1번 구간은 캐시 재사용했으며, 4~10번은 다시 `deferred`로 보류됐다. 전체를 재분석하지 않고 체크포인트부터 이어가는 동작을 실제 GPT 환경에서 확인했다.

GPT 응답의 숫자 근거 ID가 문자열로 직렬화되는 형식 차이를 입력 단계에서 정규화했다. 청크 ID가 숫자로 안전하게 변환되는 경우에만 허용하고, 임의 값·근거 인용문·관계 구조에 대한 기존 엄격 검증은 유지한다. 관련 GPT 분석 48개와 백엔드 전체 201개 테스트, 프론트 production build, macOS sidecar 재빌드를 통과했다.

장편 재개 검증을 반복할 수 있도록 `scripts/validate_long_gpt_resume.py`를 추가했다. 기존 SQLite·Chroma 체크포인트를 삭제하지 않고 `--batch-limit`만큼 보류 구간을 재개하며, `--dry-run`으로 네트워크 요청 없이 현재 구간 상태를 확인할 수 있다. 강제 중단으로 남은 실행 중 상태는 앱 재시작 시 `mark_running_jobs_interrupted`가 실패/중단 구간으로 닫는 현재 복구 경로를 통해 정리된다.

재개 도구의 `--dry-run`을 실제 장편 체크포인트에 실행해 `failed` 상태, 완료 구간, 남은 구간 상태를 네트워크 요청 없이 JSON으로 재현했다. 백엔드 201개·프론트 107개 테스트가 다시 통과했다.

같은 10회차 저장소에서 실제 `gpt-5.6-luna / low`로 마지막 보류 구간 1개만 재개했다. 계정 상태는 `connected · prolite`, 신규 GPT 요청 1회, 기존 체크포인트 재사용 9회, 총 18.56초였으며 엔티티 5개·관계 5개·충돌 후보 1개를 반환하고 전체 작업 상태가 `completed`가 됐다. 전체 원고를 다시 보내지 않고 마지막 구간만 처리한 결과다. 결과 JSON은 `output/validation/long-gpt-20260913/resume-batch-1.json`에 저장했다.

다중 원고 가져오기에서 개별 파일 실패를 성공 수에 묻지 않도록 보완했다. 파일 선택과 Finder 드래그 앤 드롭 모두 성공·실패 편수를 별도로 안내해 장편 업로드 중 일부 누락을 즉시 재시도할 수 있다. 프론트엔드 107개 테스트, production build, `verify-desktop.sh`를 통과했다.

분석 진행 패널에 완료된 비재사용 구간의 평균 처리 시간으로 계산한 잔여 시간 추정치를 추가했다. GPT 응답 편차를 감안해 참고용 문구로 표시하며, 재사용 구간은 계산에서 제외한다. 테스트 107개와 production build를 통과했다.

웹소설 회차 크기에 가까운 실제 임베딩 측정도 추가했다. 새 임시 작품에 회차당 약 116,500자씩 3회(총 349,479자·828청크)를 넣고 설치된 EmbeddingGemma 300M으로 색인한 결과 118.55초(초당 6.985청크)였다. 같은 텍스트 밀도를 단순 선형 적용하면 10회는 약 6분 35초로 추정되며, 실제 시간은 문단 구조·장치 상태에 따라 달라진다. 이 결과는 GPT 요청 시간과 의미 정확도를 포함하지 않는다. 측정 원본은 `output/validation/long-gpt-20260913/real-40k-embedding.json`에 보존했다.

기존 Qwen RAG 수명주기 검증 결과도 재확인했다. 50회차 성장 색인, 변경 없는 재실행, 앱 재시작, 18화 수정본 교체, 삭제, 회차 필터, 작품 격리, 51화 추가까지 13개 검사가 모두 통과했다. 수정본 교체에서는 변경된 문서의 3개 청크만 임베딩했고, 나머지 청크는 재사용했다.

웹소설 규모 상한을 가늠하기 위해 100회·회차당 40,000자(총 400만 자)를 provider stub으로 스트레스 테스트했다. 9,090개 청크·909개 검토 구간을 33.76초에 구성했고, 시간 초과 1건을 분할·재시도해 실패 0개로 완료했다. 101회차 추가 시 신규 요청은 9개, 기존 구간 재사용은 901개였다. 이는 오케스트레이션·증분 체크포인트 검증이며 실제 로컬 임베딩·GPT 응답 시간과 품질은 포함하지 않는다.

임베딩 배치 크기를 `STORY_GUARD_EMBED_BATCH` 환경 설정으로 조정할 수 있게 했다. 기본값 4는 유지하고 1~8 범위로 제한해 저사양 장치에서는 메모리를 줄이고 고성능 장치에서는 처리량을 높일 수 있다. Qwen llama.cpp와 EmbeddingGemma 워커 모두 동일한 제한을 적용하며 백엔드 테스트 203개와 프론트 테스트 108개가 통과했다.

분석 계획 응답과 분석 화면에 로컬 임베딩 색인 예상 시간을 추가했다. EmbeddingGemma는 실측 약 7청크/초, Qwen은 2026-09-13 실제 62,000자 런타임 측정 약 1.4청크/초를 기준으로 한 참고치이며, 실제 진행률은 실행 중 기록을 우선한다. GPT 검토 예상 시간과 색인 대기 시간을 분리해 장편 첫 실행이 멈춘 것으로 보이지 않게 했다.
