# 장편 원고 범위별 분석 계약

## 목적

수백 회 원고를 한 번에 기다리지 않도록 회차 범위를 나눠 분석하되, 새 범위의 결과가 기존 관계 지도와 작가 판단을 덮어쓰지 않게 한다.

## 현재 구현의 전제

- 기본 GPT 분석은 작품 전체 스냅샷을 읽고 성공한 경우에만 그래프·이슈를 원자적으로 교체한다.
- 원고를 추가하거나 수정해도 마지막 게시 결과를 유지한다.
- 검토 구간은 내용 fingerprint와 모델·추론 강도·스키마 호환 키로 재사용한다.
- GPT 분석 API에도 회차 범위 인자를 추가했다. 범위 밖 근거는 게시 그래프에 시드하고, 선택 범위의 근거는 새 결과로 교체하는 원자적 병합 경로를 사용한다. 실제 사용자 화면에서 범위를 선택하는 UI와 네이티브 E2E는 별도 검증 대상이다.

## 필요한 저장 상태

1. `analysis_run`: 작품 ID, 대상 회차 범위, 원고 스냅샷, 모델, 추론 강도, 상태.
2. `analysis_window_checkpoint`: 실행 ID, 회차·청크 fingerprint, 상태, 응답, 근거, 오류.
3. `published_revision`: 마지막으로 전체 작품에 게시된 그래프·이슈·판단의 기준 실행.
4. 범위 실행은 먼저 임시 결과에 기록하고, 범위 밖의 게시 결과와 병합 검증을 통과한 뒤 게시 revision을 갱신한다.

## 병합 규칙

- 같은 `(type, canonical_name)` 엔티티는 기존 ID를 유지한다.
- 범위 안에서 새로 확인된 관계는 기존 관계와 `(source, target, type)`로 합친다.
- 같은 양 끝점의 관계 유형이 바뀌면 이전 관계를 삭제하지 않고 변화 기록으로 남긴다.
- 범위 밖 관계와 고립 후보는 그대로 유지한다.
- 이슈는 근거 fingerprint가 같을 때만 기존 작가 판단을 이어받는다. 근거가 달라지면 새 후보로 만든다.
- 범위 실행 실패·취소·원고 변경 시 임시 결과만 폐기하고 게시 revision은 건드리지 않는다.

## 사용자 흐름

1. 분석 화면에서 `전체` 또는 `1–10화` 같은 범위를 선택한다.
2. 시작 전에 실제 문서 자수·예상 검토 구간·새 요청 수를 표시한다.
3. 완료된 범위는 `검토 준비 완료`로 표시하고, 아직 분석하지 않은 범위는 `미검토`로 표시한다.
4. 범위를 다시 실행하면 동일 fingerprint의 성공 구간은 재사용한다.
5. 전체 범위가 게시되기 전에는 관계 지도에 게시 결과와 임시 결과를 섞지 않는다. 임시 결과는 별도 배지와 필터로만 보여준다.

## 게시 게이트

- 원고 스냅샷과 설정 fingerprint가 시작 시점과 일치한다.
- 범위 안의 모든 검토 구간이 `validated` 또는 `reused`다.
- 인용문이 현재 청크에 존재한다.
- 기존 작가 판단의 fingerprint가 보존된다.
- 병합 후 source/target이 존재하고, 범위 밖 데이터가 감소하지 않는다.

## 검증 시나리오

- 1–10화 게시 후 11–20화만 분석: 1–10화 그래프·판단 유지, 11–20화만 추가.
- 11–20화 중 한 구간 timeout: 임시 결과만 partial, 재시도 시 성공 구간 재사용.
- 1–10화 원고 수정: 수정된 fingerprint만 재실행, 수정 전 판단은 이력으로 보존.
- 범위 실행 중 설정 변경: 실행 실패, 기존 게시 revision 유지.
- 두 범위를 동시에 실행: 같은 작품에는 하나만 게시하고 나머지는 대기 또는 취소.

범위 분석 API와 병합 코드는 구현됐지만, 실제 사용자 화면의 범위 선택 UX와 네이티브 장편 원고 E2E를 통과하기 전까지 제품의 지원 상한으로 홍보하지 않는다.
