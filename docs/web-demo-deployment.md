# Story Guard 웹 데모

## 현재 구현

기존 `WorkbenchNav`, `ManuscriptsPage`, `ReviewPage`, `RelationshipExplorer`, `SourceText`를 공유합니다. 데모 전용 변경은 안내 배너, 읽기 전용 원고, 브라우저 판단 저장, 새 문장 검토입니다. 데스크톱의 기존 편집 동작은 유지합니다.

공개 샘플 「백로호텔의 마지막 손님」 10화의 실제 데스크톱 결과를 사용합니다: 엔티티 138개, 관계 205개, 검토 후보 3개. 집필 메모를 탐지 결과로 사용하지 않습니다. 원문은 `samples/baekro-hotel`과 대조했고, 근거 인용이 본문에 포함되는지 검사합니다. 계정·설정·개인 경로·요청 캐시는 내보내지 않습니다.

## 로컬 미리보기

```sh
npm run build:demo
npm run preview:demo
```

브라우저에서 `http://127.0.0.1:4173/`를 엽니다. 실시간 AI 미설정 상태에서도 원고, 그래프, 검토, 판단 저장을 사용할 수 있습니다. 정적 빌드의 루트 파일은 `demo-dist/index.html`입니다.

개발 중 `/demo`는 일반 Vite 서버에서 사용할 수 있지만, API를 포함한 검증은 위의 동일 출처 미리보기를 사용합니다. `VITE_DEMO_API_URL`은 기존 호환 설정으로 남아 있으며, 공개 운영은 별도 CORS 설정 없이 같은 출처로 제공합니다.

## 임베딩 준비

브라우저는 모델을 받지 않습니다. 고정 샘플을 짧은 원문 구간으로 나누어 Qwen으로 사전 계산하고, 새 문장만 서버에서 계산합니다. 데스크톱과 같은 `LocalLlmEmbeddings` 및 질의 지시문을 사용합니다. 데모 색인은 짧은 겹침 구간으로 따로 생성하므로 데스크톱 Chroma 검색과 결과 순위가 완전히 같다고 보장하지는 않습니다.

```sh
export STORY_GUARD_DEMO_MODEL_DIR=/absolute/path/to/models
npm run demo:index
```

모델 폴더에는 기존 `Qwen3-Embedding-0.6B-Q8_0.gguf`가 필요합니다. 결과는 `output/web-demo/index.npz`입니다. 새 문장 검토는 지정한 회차까지의 관련 원문 최대 8구간을 GPT에 전달합니다. 모델 SHA-256, 질의 지시문, 샘플 버전을 확인하여 다른 모델의 벡터와 섞이지 않게 합니다.

샘플을 갱신할 때:

```sh
python3 scripts/export-web-demo.py --database /absolute/path/to/story_guard.sqlite --project PROJECT_ID
npm run demo:index
npm run build:demo
```

내보내기는 DB를 읽기 전용으로 열고 공개 샘플과 원문 일치를 확인합니다. 공개 샘플 이외의 작품은 거부합니다.

## GPT 및 사용량 설정

현재 공개 API는 OpenAI API 키 방식입니다. 개인 ChatGPT 구독 인증을 복사하거나 공개 서버에 노출하지 않습니다. 구독 기반 공용 처리는 구현하지 않았습니다.

다음 값을 서버 환경에 설정합니다. 비밀키를 프런트 빌드 환경에 넣지 않습니다.

| 환경 변수 | 의미 |
| --- | --- |
| `STORY_GUARD_DEMO_OPENAI_API_KEY` | 서버 전용 API 키 |
| `STORY_GUARD_DEMO_MODEL` | 기본 `gpt-4o-mini` |
| `STORY_GUARD_DEMO_INPUT_USD_PER_M` | 선택 모델의 100만 입력 토큰당 USD 요금, 필수 |
| `STORY_GUARD_DEMO_OUTPUT_USD_PER_M` | 선택 모델의 100만 출력 토큰당 USD 요금, 필수 |
| `STORY_GUARD_DEMO_KRW_PER_USD` | 예산 환산에 사용할 보수적 환율, 필수 |
| `STORY_GUARD_DEMO_BUDGET_KRW` | 기본 30000 |
| `STORY_GUARD_DEMO_INDEX` | 사전 계산한 npz 파일 경로 |
| `STORY_GUARD_DEMO_MODEL_DIR` | 서버의 Qwen 모델 폴더 |
| `STORY_GUARD_DEMO_USAGE_DB` | 영속 볼륨의 사용량 SQLite 경로 |

요금·환율은 배포 시 공식 가격으로 설정해야 합니다. 이 값에 따른 내부 상한이며, 실제 환전·세금이나 이후 가격 변경까지 포함한 청구 보장은 아닙니다. 제공자 콘솔의 별도 지출 제한도 설정하십시오.

- 한국 시간 기준 쿠키 방문자당 하루 3회 성공한 검토. 쿠키 삭제로 우회 가능하므로 IP별 하루 30요청과 전체 예산을 함께 제한합니다.
- 한 서버 프로세스는 분석 슬롯 4개를 제공합니다. 따라서 서로 다른 방문자 4명까지는 각자의 입력으로 GPT 검토를 동시에 진행합니다. Qwen 임베딩 모델은 공유 메모리의 단일 인스턴스를 짧은 잠금으로 보호하고, 시간이 오래 걸리는 GPT 호출은 잠금 밖에서 실행합니다.
- 5번째 동시 요청은 `429`와 재시도 안내를 받으며 사용 횟수·비용 예약을 만들지 않습니다. 현재 정책은 무한 대기열 대신 빠른 재시도입니다. 심사 환경에서 요청이 몰려도 화면에 다른 방문자의 결과가 나타나지 않도록 결과는 요청 함수 안에서만 생성하고 응답으로 반환합니다.
- 쿠키 방문자별 하루 3회 제한은 분석 시작 전에 `running` 예약으로 계산합니다. 같은 방문자의 동시 요청도 3건까지만 예약되고 4번째는 비용 없이 거절됩니다. IP별 제한과 전체 예산 예약은 SQLite `BEGIN IMMEDIATE` 트랜잭션으로 함께 보호합니다.
- 이 동시성 상한은 단일 Uvicorn 프로세스·인스턴스를 전제로 합니다. 여러 워커나 인스턴스로 확장하면 각 프로세스의 슬롯이 따로 생기므로, 그 경우 Redis 같은 중앙 세마포어와 중앙 사용량 저장소를 추가해야 합니다. 심사 데모는 아래 실행 예처럼 `--workers 1`로 유지합니다.
- 호출 전 최대 비용을 SQLite 트랜잭션으로 예약하고, 응답 사용량으로 정산합니다. 통신 결과가 불확실하면 비용 예약을 보존하고 같은 요청을 재실행하지 않습니다.
- 서버 재시작에도 사용량은 보존됩니다. 브라우저의 판단 초기화는 AI 사용량을 초기화하지 않습니다.
- 사용량 DB에는 입력/출력 본문 없이 요청 해시·상태·비용만 저장합니다. 원 IP 대신 날짜별 해시를 보관합니다. API 요청은 `store:false`를 사용합니다. 제공자 측 데이터 처리 정책은 별도로 적용됩니다.
- 실시간 결과와 사용자가 입력한 문장은 브라우저 메모리에만 둡니다. 분석 화면을 벗어나 컴포넌트가 해제되면 진행 중인 브라우저 요청을 취소하고 결과 상태를 폐기합니다. 서버는 이미 외부 API로 전송을 시작한 요청을 강제로 되돌릴 수 없으므로, 그 경우 예약 비용은 불확실 호출로 보존합니다.
- 실시간 분석이 완료되면 해당 방문자의 브라우저 상태에만 임시 검토 이슈 1개를 추가합니다. 관계 지도는 새 문장을 엔티티로 만들지 않고, 검색된 기존 엔티티를 중심으로 영향받은 기존 관계와 원문 근거를 보여 줍니다. 원본 snapshot·서버 DB·다른 방문자 화면은 변경하지 않으며, 데모를 나가거나 첫 사례로 돌아가면 임시 이슈를 폐기합니다.
- 예산 80% 도달 시 서버 로그에 경고를 기록합니다. 자동 외부 알림과 가동 시간 모니터는 아직 연결하지 않았습니다.

## 배포 경계

`backend.app.demo_server:app`만 실행합니다. 기존 `backend.app.main:app`은 데스크톱 DB·파일·계정 API이므로 공개하지 않습니다. 데스크톱에 있던 간이 공개 데모 엔드포인트는 제거했습니다.

`pip install -r backend/requirements-demo.txt`로 공개 서버 전용 의존성을 준비합니다. CPU 서버에 프런트 정적 빌드, 샘플 JSON, Qwen 모델, npz 색인, Python 런타임을 배치하고 사용량 DB를 영속 볼륨에 둡니다. `uvicorn backend.app.demo_server:app --host 0.0.0.0 --port 8000 --workers 1`을 HTTPS 프록시 뒤에서 실행합니다. 단일 프로세스를 전제로 하며 여러 워커·인스턴스로 늘리지 않습니다. 프록시 환경에서는 신뢰할 프록시 주소만 `--forwarded-allow-ips`로 지정하여 원 IP가 정확히 전달되게 합니다.

사이트 루트와 `/api/demo/*`는 동일 출처여야 합니다. 공개 전 API 키 연결, 배포 CPU의 메모리·검색 지연, HTTPS 쿠키, 새 브라우저 접속, 외부 가동 시간 점검을 확인합니다. 로컬 미리보기만으로 배포 완료라고 판단하지 않습니다. 심사 기간 2026-09-21~2026-10-17 동안 서비스를 유지합니다.

## 원본 Mac 없이 배포하는 독립 묶음

`npm run build:demo`만 실행하면 원고·관계·검토 결과는 웹 JS에 포함되지만, 서버 임베딩 모델과 인덱스는 포함되지 않습니다. 아래 명령은 이 파일들까지 명시적으로 묶습니다. 웹 화면만 배포할 때와 혼동하지 마십시오.

```sh
npm run build:demo
.venv/bin/python scripts/package-web-demo.py \
  --output output/web-demo-release-NEW_VERSION \
  --model-dir /absolute/path/to/models
.venv/bin/python scripts/verify-web-demo-package.py output/web-demo-release-NEW_VERSION
```

기존 출력 폴더가 있으면 덮어쓰지 않고 중단합니다. 묶음에는 최소 API 소스, Python 의존성 목록, 웹 빌드, 샘플 JSON, 모델과 인덱스, SHA-256 manifest, `start.sh`가 포함됩니다. 개인 DB·쿠키·로그인·API 키·사용량 DB는 포함하지 않습니다. 새 서버에서 Python 의존성을 설치하고 `start.sh`를 실행합니다. 원래 Mac의 앱 데이터 경로를 연결할 필요가 없습니다.

### 변경되지 않는 데이터와 변경되는 데이터

| 데이터 | 위치 | 재배포 때 처리 |
| --- | --- | --- |
| 공개 샘플 원고·그래프·검토 결과 | 배포 묶음의 snapshot 및 웹 빌드 | 같은 버전 그대로 재배포 가능 |
| 샘플 임베딩·Qwen 모델 | 배포 묶음의 assets | 함께 배포, manifest로 손상 검사 |
| AI 일일 횟수·비용 | 별도 영속 볼륨의 SQLite | 앱 교체와 분리, 삭제하지 않음 |
| 방문자의 작가 판단 | 방문자 브라우저 localStorage | 같은 브라우저/주소/샘플 버전이면 유지; 브라우저 데이터 삭제 시 초기화 |

공개 실행 예:

```sh
STORY_GUARD_DEMO_USAGE_DB=/data/storyguard/usage.sqlite \
DEMO_HOST=0.0.0.0 PORT=8000 ./start.sh
```

`/data`는 호스팅 서비스의 영속 볼륨으로 마운트해야 합니다. 경로 설정만으로 호스팅 디스크가 영속화되지는 않습니다. `start.sh`는 공개 주소로 실행할 때 사용량 DB 경로를 명시하지 않으면 중단합니다. HTTPS 프록시와 API 키/가격 설정도 별도로 필요합니다.

영속 볼륨 자체의 장애·삭제까지 대비하려면 호스팅 백업을 활성화하거나 SQLite backup API로 별도 저장소에 백업하십시오. 현재 공개 호스팅과 외부 백업은 아직 연결하지 않았습니다.

검증 스크립트는 빈 작업 디렉터리와 별도 데이터 경로에서 묶음의 API/샘플/모델만 불러옵니다. 원고 10화, 관계 205개, 실제 Qwen 검색을 확인하고, 사용량을 기록한 뒤 새 프로세스에서 남은 횟수가 유지되는지 검사합니다. 원본 데스크톱 API 모듈은 로드하지 않습니다.
