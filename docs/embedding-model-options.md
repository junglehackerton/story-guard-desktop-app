# 임베딩 모델 선택과 처리 시간

- 환경 설정에서 Qwen Q8(약 639MB), EmbeddingGemma 원본(약 1.27GB)을 선택하고 준비·적용한다.
- 선택한 임베딩 모델만 준비하며 로컬 생성 모델은 함께 다운로드하지 않는다.
- 기존 선택은 유지한다. 모델별 인덱스를 분리하며 기존 모델로 돌아오면 변경 없는 인덱스는 재사용한다.
- Gemma는 전용 Python 프로세스에서 Sentence Transformers FP32로 실행한다. CUDA → MPS → CPU 순으로 사용 가능한 장치를 선택한다. 문서 배치 크기는 8, 입력 2,048토큰 초과는 자르지 않고 오류로 알린다.
- Gemma 실행 환경을 앱 Python에 직접 설치하지 않는다. Chroma 0.5.23과 Transformers 5의 tokenizers 요구 버전이 다르다. 소스 실행에서는 전용 gemma-runtime 가상환경을 자동 준비한다. 개발 환경의 기존 평가 가상환경도 재사용할 수 있다. 경로는 STORY_GUARD_GEMMA_PYTHON으로 명시할 수 있다.
- Gemma의 Hugging Face 이용 조건 동의·로컬 인증이 필요하다. 실행 런타임과 모델은 별개 용량이다.
- PyInstaller 독립 배포본에 격리 Python 런타임을 포함하는 작업과 Windows 실기 검증은 아직 남아 있다. 준비되지 않은 배포본에서는 설치 오류를 명시한다.

## 실측

동일한 50회차 합성 원고 121,372자·152청크·40질의:

- Gemma CPU 4스레드, 단건: 최초 임베딩 66.0초, Top4 29/40.
- Gemma 자동 가속 + 8개 배치 + 프로세스 통신: 임베딩 21.27초, Top4 29/40. 최초 준비 10.48초 별도.
- 두 실행의 가속·배치 효과를 합친 비교이며 배치만의 효과를 분리 측정한 것은 아니다.
- 이 실측은 전체 문서 목록을 배치로 전달한 어댑터 측정이다. 앱은 문서별 동기화를 수행하므로 문서가 짧으면 실제 배치가 8보다 작을 수 있다. 전체 UI 업로드→인덱싱 시간이나 GPT 시간은 아니다.

## 다음 최적화

1. 실제 앱에서 여러 문서의 변경 청크를 모아 배치 처리하되, 취소·실패 복구와 진행률을 유지한다.
2. 수정 문서 안의 동일 텍스트는 모델별 해시 캐시로 재사용한다. 현재는 변경 없는 문서를 재사용하지만 수정 문서는 새 청크 ID를 만들므로 해당 문서가 재임베딩될 수 있다.
3. 배치 크기를 RAM/VRAM과 입력 길이에 맞춰 조정하고 메모리 부족 재시도를 검증한다.
4. 실제 작가 원고와 Mac/Windows 기기에서 재측정한 후 기본 모델을 결정한다.
