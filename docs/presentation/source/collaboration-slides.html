계약과 도구

검토한 API 모델에서 OpenAPI와 TypeScript 타입을 생성하고, 엔진 입출력은 별도 버전 있는 모델로 정의하는 제안입니다. OpenAPI만으로 시간 의미·교정 보존·취소 동작까지 검증되지 않습니다. 실제 제공자 응답과 의미 규칙을 검사해야 합니다.

MSW는 모킹 도구 후보입니다. Pact의 양쪽 계약 검증 원리를 참고하되, 별도 Broker 도입을 전제로 하지 않습니다. FastAPI·생성기·모킹 도구는 현재 저장소와의 호환성을 확인하고 버전을 고정해야 합니다. CODEOWNERS와 브랜치 보호의 지원 범위는 GitHub 요금제·저장소 공개 여부를 확인해야 합니다.

운영과 비용

각 개발 환경의 DB·포트·설정을 분리합니다. worktree는 이 런타임 자원을 자동 분리하지 않습니다. PR 기본 검사는 외부 AI 없이 실행하고, 실제 임베딩·GPT·인증·배포는 정해진 자원 안에서 별도 검증합니다. Mock의 성공을 실제 분석 품질 증거로 제시하지 않습니다.

C의 범위가 넓으므로 웹 화면·샘플은 A, 모델 설치·자원 측정은 B가 담당합니다. 각자 테스트하고 리뷰 담당을 순환합니다. 팀원 역량·작업 가능 시간·지원 OS·AI 연결 호환성은 추가 결정 대상입니다.
